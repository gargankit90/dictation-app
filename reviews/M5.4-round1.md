## Findings

### R1 — Major: the publish guard accepts a different tag

**Location:** `scripts/release.sh:104` (regression coverage: `scripts/test-release.sh:229`).

`grep -qx "v$version"` treats the version's dots as regular-expression wildcards. For version `0.3.0`, a clean HEAD tagged only `v0x3x0` passes this check even though `v0.3.0` does not exist. The script reads the signing items, builds, and calls `gh release create v0.3.0`. This breaks the explicit release precondition in acceptance criterion 2: publishing must require the exact version tag on HEAD.

**Reproduced without owner secrets or publishing:** in an isolated copy, change the existing wrong-tag fixture from `git -C "$repo" tag "v0.2.9"` to `git -C "$repo" tag "v0x3x0"`, then run `bash scripts/test-release.sh`. It exits 1 with `test-release: FAIL: --publish passed with another version's tag`; the captured stub run says `release: publishing v0.3.0`. The fixture uses generated throwaway keys and a stub `gh`; no release was created.

**Suggested fix:** compare tags literally, for example `grep -qxF -- "v$version"`, and retain a lookalike-tag regression case. Assert that this refusal happens before reading either signing item, building, or calling `gh`, as the dirty-tree refusal already does.
