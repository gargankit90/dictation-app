## Findings by severity

### R1 — major: production updater and dialog plugins are never registered

**Location:** `src-tauri/src/updater.rs:213`, also `src-tauri/src/updater.rs:130` and `src-tauri/src/lib.rs:239`.

The production `tauri::Builder` registers only the overlay plugin. Neither
`tauri_plugin_dialog::init()` nor `tauri_plugin_updater::Builder::new().build()`
is registered. `DialogExt::dialog()` reads managed `Dialog` state and
`UpdaterExt::updater_builder()` reads managed `UpdaterState`; those states are
installed by the corresponding plugin setup, and Tauri's `state()` panics
when they are missing.

**Concrete failure:** choose **Check for updates…** in the shipped build.
The empty public key returns `NotConfigured`, then `app.dialog()` panics in
the spawned task instead of showing “Updates aren't set up.” Configuring a
key does not fix the feature: `app.updater()` then panics first. The updater
cannot find or install the test release required by criterion 4.

**Suggested fix:** register both plugins on the production builder, preserving
the absence of their JavaScript permissions in both capabilities. Add a
regression check using the production plugin-registration path. The existing
`app_for` helper registers its own updater, so all 12 unit tests pass while
the application remains broken.

[Inline finding](https://github.com/gargankit90/dictation-app/pull/131#discussion_r4437258592).

### R2 — minor: package downloads do not enforce HTTPS or project location

**Location:** `src-tauri/src/updater.rs:179`.

The manifest endpoint is fixed to this project's HTTPS GitHub Releases URL,
but the package URL from that manifest is passed directly to the plugin.
In pinned `tauri-plugin-updater` 2.14.1, `Update::download()` explicitly only
warns about an HTTP package URL even when
`dangerousInsecureTransportProtocol` is false. It also accepts other hosts
and uses the HTTP client's default redirects. A mistakenly published HTTP
or unrelated-host URL therefore causes a fetch from that destination after
the user accepts. Minisign and signed-version verification still protect
executable integrity; this is not an unsigned-install bypass.

**Suggested fix:** validate package HTTPS/project release URLs before fetching
and constrain redirects while allowing GitHub's legitimate HTTPS asset CDN.
Cover HTTP, unrelated hosts and insecure redirects, keeping local HTTP test
overrides separate from production policy.

Tracked as nonblocking [tech-debt #134](https://github.com/gargankit90/dictation-app/issues/134).
[Inline finding](https://github.com/gargankit90/dictation-app/pull/131#discussion_r4437258669).
