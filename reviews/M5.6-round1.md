## Findings

### R1 — Major: the cleanup releases a physically held Command

**Location:** `crates/platform/src/insert/macos.rs:388` (posted at line 430).

`before.difference(flags | key_bits)` removes both Command sides even when
they describe a real held key. For example, finish a dictation using
`Cmd+Space`, release Space while continuing to hold Command, and let the
transcription paste. The plan ends with a left-Command `FlagsChanged`
event with no Command mask or device bits. An app observing modifier
changes receives a Command release while the user still holds it. This
also affects right Command: the release strips its bit as well. This is a
new false release, rather than merely clearing the synthetic paste's state.

The app's own listener treats these flags as authoritative:
`third_party/handy-keys/src/platform/macos/listener.rs:191` and its
`FlagsChanged` branch at line 357 reconcile the held modifiers from the
event. There is no synthetic-event exclusion. A real Command pressed after
the snapshot at line 409 also cannot be represented by the precomputed
cleanup. Applications that maintain Command-held state therefore see the
wrong state at cleanup, including the hotkey listener.

**Reproduction:** outside the repo, copied the exact production planner
and its four new tests into `/tmp/m56-review-harness/src/paste.rs`. Added:

```rust
let held = CGEventFlags::MaskCommand | CGEventFlags::from_bits_retain(0x8);
let events = paste_events(
    PasteChord { modifier: ChordModifier::Command, key_code: 9 },
    held,
);
assert!(events[2].flags.contains(held));
```

All four PR paste tests pass; this assertion fails with
`held=0x100008 final=0x0`. The existing "already set" test deliberately
expects this same clearing, without distinguishing synthetic contamination
from a physical hold. The reproduction constructs no OS events and posts
no input. It proves the false-release plan; physical keyboard behavior was
not exercised on the owner's screen or in a VM.

**Suggested fix:** distinguish physically held modifiers from modifiers
owned by the synthetic paste, and release only the latter. Preserve the
real left/right Command state at cleanup, including changes during the
paste. Use physical input tracking or an isolated event-source strategy
whose interaction with session state is verified; simply retaining the
earlier aggregate Command flag would reintroduce the original stuck-key
bug. Add tests for left/right/both Command held before paste and a real
modifier changing during the sequence, alongside the no-held-key regression.
