## Findings by severity

### B1 — A lost release followed by another modifier transcribes instead of discarding

**Blocker — `third_party/handy-keys/src/platform/macos/listener.rs:367–368`**, with the exclusion at `:270`.

The new `after_flags_changed` reconciles every modifier group, but its caller sends no resync when this repairs an unrelated modifier. Reproduction: Right Option down starts recording; its release is not delivered; two seconds later Left Shift down arrives with Shift flags and no Option. The callback silently clears tracked Right Option and emits only the Shift press. The real matcher emits `Released`, and the real coordinator issues `StopRecording` and `Transcribe`. The recording includes the interval after the user released Option and is uploaded rather than discarded. This is the milestone's explicit scope item “or a release is otherwise lost”; it does not require an observed tap-disable pseudo-event.

The external test `retro_safe::review_missed_release_followed_by_shift_transcribes` calls the actual patched callback using local, unposted CGEvents, production conversion functions, the production matcher, and the actual coordinator. Its assertions deliberately confirm the defect:

```text
missed Option release, next Shift => [KeyEvent { modifiers: Modifiers(SHIFT_LEFT), key: None, is_key_down: true, changed_modifier: Some(Modifiers(SHIFT_LEFT)) }]
mapped=Some(Released); after 2s => Transcribing, [StopRecording, Transcribe, StateChanged(Transcribing)]
```

**Suggested fix:** detect unexplained corrections on `FlagsChanged` too. Exclude the change legitimately described by that event's keycode, but send a resync before the ordinary event if another tracked modifier changed. Handle Caps Lock and Fn events consistently. Do not treat a normal Shift/Cmd transition while Option remains held as a loss. Add callback-to-matcher/coordinator regressions for missed Option release followed by another modifier, expecting `Interrupted`, `DiscardRecording`, and zero transcription, alongside normal modifier-transition checks.

## Normal holds and callback work

An independent callback/matcher test holds Right Option while pressing/releasing Shift and Right Cmd, typing A, toggling Caps Lock, pressing/releasing Fn, and clicking/releasing a mouse button. It runs with hardware-style device bits and again with group-only synthetic flags: **15 intermediate events in each run, 0 false resyncs, 0 false releases**, followed by exactly one final release. This checks deterministic input sequences, not real hardware timing or every keyboard layout.

Reviewed `85db3b0..97374ec`: changes are limited to modifier helpers, callback direction/recovery, startup snapshot, resync representation, nine tests, patch notes and NOTICE. Verified **35/35** original vendored files byte-identical to the cached published crate at `85db3b0`; the only extra file there is the documented `rustfmt.toml`. The patch is localized, but the reconciliation gap prevents calling it fully correct.

New modifier calculations use fixed tables and bit operations: no heap collection, logging, sleep, I/O or new lock is added on the normal callback path. Recovery adds sends through the existing unbounded `std::sync::mpsc` channel; those sends can allocate, and the callback already takes a mutex. Therefore a literal “no new allocation or blocking” guarantee would be inaccurate: no new explicit allocation or blocking primitive is introduced, but an extra recovery send can allocate and use channel synchronization. Matcher reset, logging, sink delivery and failure processing execute on the adapter thread.

The patch adds no production unsafe blocks or changes to refcon ownership, tap/run-loop teardown, or FFI signatures. The new test-only unsafe callback call keeps both the CGEvent and CallbackCtx alive synchronously. Upstream unsafe blocks do not uniformly use literal `// SAFETY:` comments; that pre-existing dependency style is retained, rather than extending app unsafe outside the platform adapter. No new unsound lifetime was found. Platform's new code is safe Rust; the existing stop/join path is reused for failed listeners. The IOKit SDK's `NX_DEVICE*KEYMASK` constants match the four group tables.
