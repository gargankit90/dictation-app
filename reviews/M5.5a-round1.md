## Findings

### B1 — Blocker: the fallback reads the entire focused field

**Location:** `crates/platform/src/cursor/macos.rs:307-309`.

If `AXStringForRange` is unsupported, unavailable, or returns an error mapped
to `Failed`, `units_before` requests `AXValue`. This transfers the entire
field into this process; limiting the subsequent `CFStringGetCharacters`
copy to two units does not limit the preceding IPC read. A long document or
message draft is therefore read even though only its preceding character
is needed. This violates the milestone's explicit privacy bound, "at most
a few characters before the cursor." Immediate release and the absence of
logging do not satisfy that bound. The PR description acknowledges this
behavior.

**Suggested fix:** remove the whole-value fallback and return `Unavailable`
when the bounded range API cannot supply the requested text. Any alternative
must bound the read at the source. Add a synthetic adapter test asserting
that unsupported range reads never request `AXValue`.

**Evidence:** a harness under `/tmp` used the actual adapter implementation,
synthetic AX responses, and real Core Foundation strings. With
`AXStringForRange` returning `AX_ERROR_PARAMETERIZED_ATTRIBUTE_UNSUPPORTED`,
its `AXValue` responder returned a synthetic million-unit field. Output:

```text
AXValue fallback received 1000000 UTF-16 units for a two-unit request
Copied only 2 units AFTER the whole field was received
```

No real application's text was accessed. Harness generation and execution:
`python3 /tmp/m55a-build-harness.py`,
`rustc --edition 2024 /tmp/m55a-cursor-harness.rs -o /tmp/m55a-cursor-harness`,
then `/tmp/m55a-cursor-harness`.

### M1 — Major: null ownership conversion traps instead of falling back

**Location:** `crates/platform/src/cursor/macos.rs:110-111`
(`Drop` calls `CFRelease` at line 139).

`bool::then_some` eagerly constructs its argument. For a null input,
`Self(object)` is constructed and then dropped when the condition is false,
so `CFRelease(null)` executes. A null result from a CF allocation or a
successful AX response with no object therefore terminates the process
instead of reaching the intended `Unavailable`/`Failed` fallback. This
breaks the wrapper's non-null ownership invariant and the safety argument
in `Drop`. The trigger is a null API result, not ordinary successful reads.

**Suggested fix:** use an explicit null check before constructing `Self`,
or lazy `then(|| Self(object))`; add a unit test that `Cf::owned(null)`
returns `None` without releasing anything.

**Evidence:** `/tmp/m55a-cursor-harness null` invokes the unchanged
`Cf::owned(std::ptr::null())` against real Core Foundation. It printed
`Calling Cf::owned(null), whose documented result is None` and terminated
with exit status **133** instead of returning `None`. AX IPC was stubbed;
this reproduction neither accessed the screen nor queried another app.
