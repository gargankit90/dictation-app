## Findings and integration checks

- **Single instance and delivery: OK.** `src-tauri/src/lib.rs:198` still acquires the platform single-instance lock before building the shell; the former plugin remains removed. Setup starts the pipeline, handles initial flags, and only then starts `listen_checked` (`lib.rs:340–362`). Failed injection still returns `Rejected`; restoring the success log text did not change acknowledgement semantics. Singleton ownership remains managed until shutdown after the pipeline stops.
- **Engine wiring: OK.** The merged setup retains the settings-built `Transcribers`, fixed mock choice, managed `AppConfig` and `LiveEngine`, and background rebuild (`lib.rs:273–335`). Startup constructs the unavailable/pending engine without reading the keychain. `engine.rs` is identical to merged main: shared `KeyReads`, bounded waiting, stale-read invalidation and settings/key-triggered rebuilds remain intact. The conflicting Cargo entries preserve both `tauri-utils` and Tokio's `time` feature.
- **Command ACL: OK.** M4.4 changes the implementations of `save_settings` and `set_api_key`, adding managed engine state, but adds no IPC command. All five registered commands (`get_settings`, `save_settings`, `set_api_key`, `has_api_key`, `test_api_key`) remain in `COMMAND_NAMES`; `build.rs` supplies that list to `AppManifest`. The sole capability grants exactly those permissions to `main`, with no core/plugin permissions or remote capability. The generated-ACL resolver tests passed after removing stale artifacts.
- **Debug key commands: OK.** `run_key_commands` executes before single-instance acquisition, in the launching process, and exits without forwarding. A message arriving directly through the forwarding socket only reaches `handle_flags`, which warns and ignores `key_commands`; it never calls the keychain command executor. `TEST_FLAGS = cfg!(debug_assertions)` gates parsing, so release launches cannot execute either key hook. This is behavioral exclusion from release builds: the source helper and flag names need not be literally absent from the binary. Existing tests exercise parsing with release flags disabled. No keychain access was performed during this review.
- **Log format/privacy: OK.** `lib.rs:426` restores the exact `test hook` text and field order expected by the e2e scenarios. Fields are the `HotkeyEvent` enum, the fixed launch-source string, and a delivery boolean; no key, audio or transcript is included. Failed delivery retains its warning and rejection.
