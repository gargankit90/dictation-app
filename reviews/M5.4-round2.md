## Findings and resolution

- **R1 (major): fixed.** `src-tauri/src/lib.rs:239` now builds through
  `updater::plugins`, which registers both the updater and dialog plugins
  (`src-tauri/src/updater.rs:134`). The production plugin regression test
  builds through that same helper and accesses both plugin-managed states.
  Dropping the dialog plugin makes `app.dialog()` panic; dropping the updater
  makes `updater_for()` panic through `app.updater_builder()`. Those are the
  same accesses the tray action uses. The additional source assertion catches
  removing the helper call from the production builder, and the real-config
  test checks that plugin setup accepts the shipped configuration.
- **R2 / [#134](https://github.com/gargankit90/dictation-app/issues/134)
  (minor): fixed.** `install()` validates the package URL before calling
  `download_and_install`: production requires HTTPS, the configured endpoint's
  host and port, and this repository's `/releases/` path. The manifest endpoint
  remains fixed in the shipped configuration. The client callback is carried
  into both manifest and package requests by pinned updater 2.14.1: redirects
  require HTTPS on `github.com` or a `*.githubusercontent.com` asset host, with
  a hop limit. HTTP, another repository, unrelated/lookalike hosts, insecure
  redirects and excess hops are covered. The explicit insecure test config
  preserves the local HTTP harness; it is absent from production config.
  Minisign verification and `requireSignedVersion: true` remain enforced.
- **Tester signature-message note: fixed.** Signature, encoding and signed
  version errors now share a clear refusal message at check and install time.
  The garbled-manifest and tampered-package tests exercise the error path,
  rather than only comparing message constants.
- **Private repository limitation: documented.** The tester README and PR
  notes explain that anonymous release checks cannot reach a private
  repository and direct testers to the supplied DMG. The shipped public key
  is still empty, so this build first reports that updates are not configured;
  after configuring a key, the private endpoint remains inaccessible. This
  review does not claim a working public update service.

## DMG test and manual evidence limits

`e2e_dmg_install` is an honest scripted installation check: it verifies and
mounts the DMG, copies its app to the VM application path, verifies the copied
signature and bundled notice, explicitly applies and clears quarantine using
the README command, then launches that copied app and checks a tone/mock
dictation reaches TextEdit. `launch_full` resolves to `open` on `VM_APP`, so
it does not silently run the preinstalled build. Required scenario failures
propagate to the harness exit status.

It explicitly excludes Gatekeeper UI and permission prompts; it uses a debug
build, tone audio and a mock transcriber. It therefore does not prove real
microphone quality, real-provider dictation, permission retention across an
update, or a working signed release update. The coordinator reports a fresh-VM
run of 13 passed, 0 failed, 1 skipped, including this scenario; I did not use
the VM or independently rerun that suite. Lead manual checks remain a merge
condition. This task does not merge.
