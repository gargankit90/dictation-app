## R1: failed key-hold cleanup — fixed

- `tests/e2e/scenarios/e2e_held_at_launch.sh:11` and
  `tests/e2e/scenarios/e2e_hold_release.sh:9` arm cleanup before any key-down.
  `tests/e2e/lib_full.sh:196` captures the original exit status before
  diagnostics, disables its traps, performs best-effort cleanup, and exits
  with that saved status. Cleanup failures therefore cannot replace the
  original failure. Normal completion disarms EXIT before doing cleanup.
- `tests/e2e/lib_full.sh:184` cancels outstanding Terminal jobs, quits the
  app, posts an extra key-up, closes documents and closes Terminal. The
  extra up is safe after a job's own release: it cannot leave the key down,
  and the app is stopped before this final up. The handler does not recurse.
- `tests/e2e/lib_full.sh:144` gives the generated hold its own EXIT release
  and signal-to-exit traps. It marks the key potentially down before posting
  down, clears that mark after normal up, and uses a background sleep plus
  `wait` so a signal interrupts the hold promptly. Timeout cancellation at
  `:125` targets the job script, with a bracket pattern that excludes the
  cancelling command itself, and returns failure.
- Independent local probes sourced the actual helpers and failing launch
  scenario, replacing only environmental boundaries. Launch failure 73
  remained exit 73 even when diagnostics and cleanup commands failed;
  diagnostics, release and all cleanup steps ran, with exactly one final
  up. INT and TERM returned 130 and 143 respectively, each with one cleanup.
  Normal completion returned zero without a second EXIT cleanup.
- A separate probe executed the actual generated hold in zsh with fake
  `open` and `osascript` functions. TERM during its eight-second wait caused
  exactly down/up and exited within two seconds. No host GUI was accessed.
  These probes catch the original missing-trap failure, cleanup overwriting
  the scenario status, duplicate EXIT cleanup and deferred signal handling.

The Terminal wrapper's `.done` denotes completion rather than command
success; the scenarios still require exact down/up output and successful
state/paste assertions. An injected hold failure lacks the required output
and fails those assertions; it cannot turn the scenario into PASS.

## R2: rapid paste order — fixed

`tests/e2e/scenarios/e2e_rapid.sh:12` supplies distinct mock replies
`one,two,three,four,five`; `:33` compares the entire trimmed document with
`onetwothreefourfive`. The five complete state sequences and final Idle
check remain. Local runs of the actual scenario with fake environmental
boundaries passed the ordered document and failed reversed/prepended,
replayed-first-result, missing-result and duplicated-result documents.

those concrete ordering/content regressions.

queued errors and falls back to its usual text after exhaustion. The new
mock tests verify order, exhaustion and error behavior. The launch flag is
debug-only: `src-tauri/src/flags.rs:50` defines `TEST_FLAGS` from
`debug_assertions`, both shell parse call sites pass that constant, and both
sequence syntax forms require it. Release-mode parser tests leave the
sequence unset. No new transcript logging was introduced by this wiring.
