| 1 | major | `crates/app/src/pipeline.rs:322` | `Runner::transcribe` (`tokio::spawn`, line 322) and `Runner::insert` (`tokio::task::spawn_blocking`, line 334) drop their `JoinHandle`s. First, if a `Transcriber` future or `TextInserter::insert` call panics (e.g., inside an HTTP/OS library or native binding), Tokio catches the panic in the dropped `JoinHandle`, `results.send(...)` never runs, and `results.recv()` never closes because `Runner` holds `self.results_tx`—permanently wedging `Runner.state` in `Transcribing` or `Inserting` with all subsequent hotkey presses and `Esc` ignored. Second, dropping the transcription `JoinHandle` means `Runner::run`'s shutdown cleanup (lines 198–200) never calls `.abort()` on an in-flight transcription task, leaving the future running (and holding `Audio` in memory) instead of dropping it to cancel the request as `Transcriber` and `Pipeline::shutdown` specify. | Keep an `AbortHandle` for the active transcription (calling `.abort()` on shutdown) and await each spawned job's `JoinHandle` (directly in `select!` or in a small forwarding wrapper), mapping any non-cancelled `JoinError` to `Event::TranscriptionFailed` / `Event::InsertFailed` with `tracing::error!` so the coordinator emits `ShowError` and returns to `Idle`. Add tests covering a panicking job recovering to `Idle` and `shutdown()` dropping an in-flight transcription future. |
| 2 | major | `crates/app/src/pipeline.rs:188` | In `Runner::run`, `tokio::select!` (lines 188–193) is unbiased and `ticks` (`tokio::time::interval`, line 184) is never `reset()` when entering `State::Recording`. First, if `Pipeline::shutdown()` is called when a `JobResult::Transcribed(job, Ok(text))` is also ready in `results`, unbiased `select!` picks `results.recv()` ahead of `shutdown.recv()` half the time and spawns a non-cancellable `spawn_blocking` `inserter.insert(&text)` *after* shutdown was signaled, pasting text despite `Pipeline::shutdown`'s contract. Second, `tokio::time::interval` fires immediately at `0ms` on the first recording and again at `0ms` after any idle gap `> tick_interval`; because `keys` stamps timestamps on the hotkey thread while `ticks.tick()` reads `self.clock.now()` when polled, an already-queued tap (`Pressed` at `t0`, `Released` at `t0 + 50ms`) can lose the race to the `0ms` tick if `clock.now() >= t0 + 5m`, transcribing and inserting an accidental tap. | Add `biased;` to `tokio::select!` with `_ = shutdown.recv() => break` first, then `keys.recv()`, `results.recv()`, and `ticks.tick()` last, and call `ticks.reset()` when starting a recording so ticks fire every `tick_interval` *after* recording starts. Add tests covering a ready transcription racing `shutdown()` and a queued tap with an advanced `FakeClock`. |
| 3 | minor | `crates/app/src/pipeline.rs:184` | Passing `Config { tick_interval: Duration::ZERO }` makes `tokio::time::interval(config.tick_interval)` panic inside the spawned task *after* `hotkey.start(...)` succeeded and `Pipeline::spawn` returned `Ok`, skipping `self.hotkey.stop()` and leaving the hotkey hook installed (#42). | Construct `tokio::time::interval(config.tick_interval)` in `Pipeline::spawn` before `hotkey.start(...)` and document a zero `tick_interval` under `# Panics` (or clamp `Duration::ZERO`) (#42). |
| 4 | minor | `scripts/gate.sh:42` | Under `set -euo pipefail`, `! cargo tree -p dictation-pipeline -e normal,build --prefix none | grep -q '^tauri'` negates the `pipefail` status of the whole pipeline: if `cargo tree` errors (`101`)—or hits `BrokenPipe` (`101`) once output exceeds the OS pipe buffer after `grep -q` exits `0` early—`!` inverts `101` to `0` and passes silently (#43). | Capture `tree=$(cargo tree -p dictation-pipeline -e normal,build --prefix none)` first so `set -e` checks `cargo tree` directly, then run `! grep -q '^tauri' <<<"$tree"` (#43). |
| 5 | minor | `crates/platform/src/fakes/hotkey.rs:93` | When `stop()` is called from inside `sink(event)` (#36), `deliver()` owns `sink` on its stack, re-locks `state` after `sink(event)` returns, skips restoring `sink` because `state.listening` is `false`, and drops `sink` at the end of the `while` block while holding `state`'s mutex—unlike `FakeHotkey::stop`, which drops `sink` outside the lock (#44). | Release `state` before dropping `sink` when `!(state.listening && state.sink.is_none())`, then re-lock to finish loop cleanup (#44). |
