## Failures

### Blocker: test-guards.sh runs its scratch-repo commands on the pushing repo

git runs hooks with `GIT_DIR` set. From a linked worktree it is an absolute
path (`<repo>/.git/worktrees/<name>`). `scripts/test-guards.sh` builds its
scratch repo with `g() { git -C "$tmp" ...; }` (lines 30–37: `init`, two
`commit`s, `switch --orphan other`, `commit`). `-C` doesn't override an
inherited `GIT_DIR`, so those commands act on the real repository, and the
script still reports "61 passed".

Seen when I pushed this report from worktree `m03-tester` (20:43):

- The shared `.git/config` got `core.bare = true`. `git worktree list` then
  showed the main checkout as `(bare)`, which breaks git in the main checkout.
- Commits `a` and `b` landed on my HEAD, then my worktree was switched to a
  new orphan branch `other` (commit `c`) with an empty index.
- The push was rejected (`non-fast-forward`). Nothing reached the remote:
  `git ls-remote origin` still shows the PR branch at b200b52.

What I restored: `core.bare` back to `false` (the main checkout is a normal
checkout with a `.git` dir), branch `other` deleted, and this worktree checked
out detached at my report commit (its working tree matched that commit
exactly).

The owner's push of b200b52 passed because it came from the main checkout,
where `GIT_DIR` is the relative `.git` and `-C "$tmp"` resolves it inside the
scratch dir. Agents push from worktrees, so every agent push hits this.

Safe repro (no push):

```sh
git init -q /tmp/victim && git -C /tmp/victim commit -q --allow-empty -m base
GIT_DIR=/tmp/victim/.git scripts/test-guards.sh            # 61 passed, 0 failed
git --git-dir=/tmp/victim/.git log --format=%s main        # b, a, base
git --git-dir=/tmp/victim/.git rev-parse --abbrev-ref HEAD # other
```

Expected: the guard tests touch only `$tmp`. Actual: they commit and switch
branches in whatever repo `GIT_DIR` names.

Suggested fix (Developer; `test-guards.sh` isn't a guard file): at the top of
`scripts/test-guards.sh`, unset `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`,
`GIT_COMMON_DIR` and `GIT_OBJECT_DIRECTORY` (or `env -u` them in `g()`). Add a
case that runs the script with `GIT_DIR` pointing at a scratch repo and checks
that repo's HEAD, branches and config are unchanged.

trigger the bug again. It is committed locally in worktree `m03-tester` and
