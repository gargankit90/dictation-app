## AlreadyExists "File exists" at the first `acquire()`

Reproduced: 8 parallel loops running the single test binary 250 times each, with 56 busy loops. Failures appeared in about 1 in 500 runs. A temporary local patch (never committed) added context to the errors in `acquire`:

- The failing call is `create_private_dir(&config.dir)` (`crates/platform/src/single_instance/mod.rs:186`), the `mkdir`. Not the lock file open, not `Server::bind`.
- The path is the test's own `temp_config()` directory `$TMPDIR/si-<pid>-0` (`unix.rs:356`). At failure `symlink_metadata` says: exists, **not a directory, not a symlink**, and the parent is a directory. `mkdir` gets EEXIST and std's `create_dir_all` only accepts that if `path.is_dir()`, which is false.
- `$TMPDIR` holds many leftover entries named `si-<pid>-<n>` that are empty regular files (mode 644), alongside about 23,000 leaked `si-*` directories. The test names its directory from the process id alone, and pids are reused, so a stale entry from an earlier process (or from a test in another worktree, several of which use the same `si-{pid}-{n}` pattern in the shared `$TMPDIR`) can sit at the path. `temp_config` runs `remove_dir_all` first but ignores its result, and `remove_dir_all` on a regular file fails with ENOTDIR, which `let _ =` hides.
- I did not find which process creates those empty files. They are not from this crate's code (`File::create` is used there only for the `.lock` file inside a directory).

**Answer: can two real launches at the same moment make one fail with "File exists"? No.** The real directory is created by `create_private_dir` with a recursive `DirBuilder`; the loser of a `mkdir` race sees `is_dir()` true and carries on. The probe test above (7,200 simultaneous groups of 8 launches under load) produced no error. In the product the error could appear only if the app's single-instance path were a regular file, which is a broken profile, not a race (the user sees a startup error naming the path).

Not a blocker for PR #111: the failure is before any code the PR touches. Suggested follow-up (test hygiene, minor): make `temp_config` use a unique name (pid plus nanos, as `single_instance_quit.rs` does) or `tempfile::TempDir`, and clean up; 23k leaked dirs in `$TMPDIR` is the larger nuisance.
