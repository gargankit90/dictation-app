## Untested behaviour found
- **Minor:** the guard in `Shared::restart` (`if !delivery.dead { return Restart::Listening }`, "a switch brought it back meanwhile") has no test. Deleting it leaves all of `hotkey_recovers` and `hotkey_settings` green. Without it, a Settings save that brings the hotkey back while the supervisor is in its backoff sleep would let the supervisor then start a second listener. Suggest a test: kill the hotkey, `deny_access(false)`, `switch(other spec)` while the supervisor sleeps (slow policy), then assert `listening() == 1` after the sleep. Not a blocker; not added by me because it needs a product-side timing seam (policy is configurable, so it is probably doable in `hotkey_recovers.rs`; left for the Developer).
- Esc *down* (first) returns `CancelPressed` before reconciling; repeats and up reconcile. Matches the code comment and the test; no stuck state results.
