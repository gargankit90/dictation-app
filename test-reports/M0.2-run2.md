1. **[Minor]** `.claude/hooks/guard-git.sh:86` — `<` and `>` redirection tokens in the `awk` lexer do not clear `flag = 0` (`if (c != "<" && c != ">") reset()`). If a shell redirection immediately follows a message flag with no intervening argument, the redirect target path is blanked to `''` in `$scan`, allowing commands that would clobber guard/hook files via shell redirection before `git`/`gh` runs:
   ```sh
   jq -n '{tool_input:{command:"git commit -m > scripts/guard-push.sh"}}' | .claude/hooks/guard-git.sh  # exits 0 (want 2)
   jq -n '{tool_input:{command:"git commit -m > .git/hooks/pre-push"}}'   | .claude/hooks/guard-git.sh  # exits 0 (want 2)
   ```
   Tracked in [#16](https://github.com/gargankit90/dictation-app/issues/16) (suggested one-line owner fix: `else flag = 0` on `<`/`>`).
2. **[Minor]** `AGENTS.md:113-116` — Pre-push hook description still reflects the pre-`06f7d75` design ("runs `scripts/pre-push`, which runs `scripts/guard-push.sh` ... and fails closed if the script is missing") rather than the installed `hooks/guard-push.sh` floor + optional checkout `scripts/pre-push` added in `06f7d75`.
