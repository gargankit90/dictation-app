## 1. A release build ignores the test flags (in the VM)

I built with `npm run tauri build -- --bundles app` (no `--debug`),
installed the app with `install_app` and launched it with `--press`, then
launched it again with `--press` and then with `--release`
([log](M1.5-vm/run2-logs/release-press.app.log)):

```
WARN dictation_pipeline::hotkey: PermissionMissing: the hotkey is off until Accessibility is granted and the app restarts …
INFO dictation_app_lib: ready hotkey=RightAlt
WARN dictation_app_lib: ignoring an unknown flag flag=--press from="this launch"
WARN dictation_app_lib: ignoring an unknown flag flag=--press from="a second launch"
WARN dictation_app_lib: ignoring an unknown flag flag=--release from="a second launch"
```

There was no `test hook` line and no `state changed` line, and one app kept
running. The missing Accessibility grant is not fatal in a release build:
`PermissionTolerantHotkey` logs it and the app starts.

## 3. Criterion 3 in the VM (release build)

- **Tray icon and no window: PASS.** The tray item is in the menu bar
  ([screenshot](M1.5-vm/run2-release-menubar-tray.png)). The main window
  exists but is hidden (`is_on_screen: false`), and nothing shows on the
  desktop ([screenshot](M1.5-vm/run2-release-launch-desktop.png)).
- **No Dock icon: FAIL.** The app's icon is in the Dock with a running dot
  ([screenshot](M1.5-vm/run2-release-dock-icon.png)), and it goes away when
  the app quits ([screenshot](M1.5-vm/run2-release-dock-after-quit.png)).
  The bundle's `Info.plist` has `LSUIElement = true`, both in the build and
  in the installed copy. Even so, `lsappinfo` reports the running app as
  `type="Foreground"`; Cua Driver, by comparison, reports `UIElement`.
  Likely cause: Tauri sets the macOS activation policy to `Regular` at
  startup, which overrides `LSUIElement`, and `src-tauri` never calls
  `set_activation_policy`. A likely fix is
  `app.set_activation_policy(tauri::ActivationPolicy::Accessory)` in
  `setup`, on macOS. I didn't check whether the plist key is still needed
  after that.
- **Settings and Quit: PASS.** Clicking the tray icon opens a menu with
  "Settings…" greyed out and "Quit dictation-app"
  ([screenshot](M1.5-vm/run2-release-tray-menu.png)). Clicking Settings does
  nothing: the menu stays open and no window appears. Quit logs
  `quit from the tray` and `stopped`. Afterwards no process is left, no crash
  report was written, and the tray and Dock icons are gone.

## 4. #58: deterministic edge tests

In `crates/app/tests/shell_flags_edges.rs` I removed `assert_quiet` and its
300 ms timeouts. Each test now queues the ignored event (a stray `--release`,
or a duplicate `--press`) ahead of a valid one on the pipeline's FIFO key
channel, then asserts that the valid event's state change comes next. After
`pipeline.shutdown()`, `ui.recv()` must return `None`, which proves no other
UI event was sent. Both tests pass and take about 8 ms in total, down from
about 1 s. The 5 s timeout stays in only as a guard against a hung pipeline.
