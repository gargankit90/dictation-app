## Code notes

- Per-`Config` `Mutex` is held across the whole write, sync and rename. A
  poisoned lock is recovered. Temp names use pid plus an atomic counter with
  `create_new`, so they are unique across `Config`s and processes.
- Failed write or rename removes the temp file (best effort).
- Settings validation happens before the lock and before any file is created,
  so an invalid save never touches the directory.

## Untested behaviour found

None blocking. Two saves from different `Config` instances on the same path
rely on unique temp names plus atomic rename (last rename wins); not
exercised here and not required by the spec.
