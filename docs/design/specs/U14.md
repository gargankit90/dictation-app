# U14: Which app you dictated into (bundle ID)

Build spec from the Design Lead, 2026-11-05. **Owner decision (replaces the earlier top-200 list):** send the bundle ID of the app people dictate into, with no list and no filtering, for now. Never window titles. **After U10 (#279)**, which changes the same privacy text.

## Why

The owner wants to see which apps people dictate into and where pasting fails. This changes a hard rule: AGENTS.md, `docs/privacy.md`, the app's own text and the website all say app names are never sent. All of them must change in this PR, so nothing says one thing while the code does another.

## What to send

- One new property, `app_bundle_id`, on the events for a finished or failed dictation only (`dictation_finished`, `dictation_failed`). Not on any other event. Not in Sentry reports, Report a problem, logs, or History (U7's rule stands).
- The value is the front app's bundle ID at the moment of the paste, such as `com.tinyspeck.slackmacgap`. If it can't be determined: `unknown`.
- **Validate it:** ASCII letters, digits, `.` and `-` only, at most 255 characters; anything else is `unknown`. So this field can't carry a path or free text.
- Browsers report only the browser's ID, never a site or URL.
- Same switch as everything else. Off or stored Off sends nothing.

## Text that must change, all in this PR

"Anonymous" should go wherever this applies: an install ID plus a list of the apps someone uses isn't anonymous, and a bundle ID can name an employer or a person (`com.acme.internal-tool`, `com.jane.myapp`). The privacy page already calls the ID pseudonymous.

## Acceptance criteria

1. [auto] `app_bundle_id` validation: a test feeds a valid ID, an over-long one, one with a slash or a space, and none; the last three send `unknown`.
2. [auto] It appears only on the dictation finished and failed events; a test covers the others. It's absent from Sentry reports, Report a problem, logs and the History file (extend `spawned_privacy` and U7's criterion 4 tests).
3. [auto] Stored Off and Off on Ready send nothing, including this value.
4. [auto] No window title, document, URL or page is read for this. The front app is read with an API that needs no extra permission (`NSWorkspace.frontmostApplication` in `crates/platform`, behind a port), and it never triggers a new permission prompt.
5. [auto] `docs/privacy.md`, What's sent, Settings, Ready, AGENTS.md and the site all use the new wording. No text says app names are never sent, or calls these events anonymous. The privacy-page test covers the new property.
6. [manual] One dictation into two different apps in the VM, through the fake telemetry port: each event carries the right bundle ID. The Design Lead checks the wording on the PR.

## Note

The owner chose this over a filtered list, "for now". If it changes later, the property and privacy text change together. I've raised the legal check before offering Vocet in the EU.
