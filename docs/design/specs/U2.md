# U2: Language picker with names; recorder in the Vocet keycap style

Build spec from the Design Lead, 2026-11-03. Rescoped with the Lead: the shortcut recorder itself shipped in K1 (#231, `src/HotkeyRecorder.tsx`). Related: #215.

## Why

Settings asks for a language **code** (`en`, `de`, `fr`) in a text field, and doesn't say which languages the selected engine can handle (Codex review, problem 6). The K1 recorder works well; it only needs the DS1 keycap look so it matches the rest of Vocet.

## Design

Design source: docs/design/design-system/index.html, the "Controls" section.

- **Keycap:** 12 px semibold. Grouped background (`--vc-bg-grouped`), 1 px `--vc-line-strong` border with a 3 px bottom border, 6 px radius, 2×8 px padding.
- **Language control:** a native-looking popup with search, placed in the Speech area of Settings.
  - The first entry is "Detect automatically", which stores `language: None`.
  - Then the supported languages by **name**, each in English plus its own name: "Hindi (हिन्दी)", "German (Deutsch)".
  - When the active engine is the on-device model, only that model's `languages` (`crates/core/src/local_models.rs`) are offered. Below the control: "Parakeet English understands English only. For Hindi and other languages, choose the multilingual model." with a link to it.
  - For Groq/OpenAI, offer the provider's supported set.

Until U3 lands, keep the current settings.css palette; only the keycap shape and spacing follow DS1.

## Acceptance criteria

1. [auto] The language text field is replaced by a picker. It shows "Detect automatically" plus languages by name: the English name, with the native name in brackets where it differs. No ISO code is visible in the UI.
2. [auto] The picker stores the same values as today: `None` for automatic, otherwise the ISO code. Existing settings files with `"language": "de"` load and show "German (Deutsch)". A file with a code the current engine doesn't support shows it as "German, not supported by Parakeet English" and keeps the value; it is not silently changed.
3. [auto] With the on-device engine, only `LocalModel::languages` for the selected model are offered. With Parakeet English selected, the helper line and the link to the multilingual model appear. Switching the engine re-filters the list. If the current choice becomes unsupported, it is flagged as in criterion 2.
4. [auto] The picker has type-to-search (e.g. "hin" → Hindi) and full keyboard support. Every option has an accessible name. A test covers search, keyboard selection and the stored value.
5. [auto] HotkeyRecorder keeps all K1 behaviour (left/right modifiers, Esc cancels, reset to default, refuses keys that can't work, pauses the live hotkey, Save disabled while listening). Its keycaps use the DS1 keycap style in Settings and onboarding. The existing K1 tests and `e2e_hotkey_recorder` still pass.
6. [manual] In the VM, in light and dark mode:
   - Settings shows the language picker with names. Choosing Hindi with Parakeet English shows the helper line.
   - The recorder's keycaps match the DS1 sample.

   Screenshots go on the PR.
