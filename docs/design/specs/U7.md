# U7: Local dictation history

Build spec from the Design Lead, 2026-11-03. Closes the history part of #216 (corrections are out of scope).
- **Depends on:** U5 (menu) and U6 (Settings → History section).
- **Owner decisions:** history is kept; the user chooses how many; the **default is the last 25**; text only.

## Why

When a paste fails, or the user wants a sentence again, there is no way to get the words back. The owner wants a short local history whose size the user controls.

## Privacy rules

These are part of the spec; docs/privacy.md must say the same.

- **Text only.** Audio is never stored (audio stays in memory unless debug mode is on).
- Stored only on this Mac, in the app's data folder, in a file readable only by the user (mode 0600).
- **Never sent:** not in analytics events, not in Sentry reports, not in Report a problem, not in logs at any level (no text or length in log lines).
- Stored per entry: the text, the time, the engine name, and whether it was pasted. **Not** the app or window it was pasted into.
- The "Copy last dictation" text from U5 now comes from history. With history Off, it stays memory-only as in U5.

## Design

- **Settings → History:**
  - **Keep recent dictations** (popup): **Off · 10 · 25 · 50 · 100**, default **25**. Caption: "Text only, kept on this Mac, never sent."
  - Then the list, newest first. Each row has the time ("2 min ago", "Yesterday 14:05"), the first two lines of text, a "Not pasted" chip when the paste failed, and **Copy** / **Delete** on hover or focus (always visible to keyboard and VoiceOver).
  - Empty state: "No dictations yet. Hold Right ⌥ and speak."
  - **Clear history…** (destructive; confirmation "Delete all 25 dictations? This can't be undone.").
- **Menu (U5):** add "History…" below "Copy last dictation". It opens Settings → History. Menu items still show no dictation text.
- **Lowering the limit** trims the oldest entries immediately after a confirmation that says how many will be deleted. **Off** deletes all entries and stops saving.

## Acceptance criteria

1. [auto] Settings has `history_limit` ∈ {0, 10, 25, 50, 100}, default **25** for new and existing installs. Settings files without the field load as 25, and invalid values are rejected with the existing validation pattern. Tests cover the migration.
2. [auto] Each completed transcription with non-empty text adds an entry {id, text, created_at, engine, pasted: bool}, written atomically to a history file in the app data folder with mode 0600. Failed pastes are stored with `pasted: false`. The list never exceeds the limit; the oldest entries are dropped first.
3. [auto] Lowering the limit trims at once after confirmation. Off (0) deletes the file's entries and stores nothing more. Clear history deletes all after confirmation. Tests cover each.
4. [auto] Privacy tests:
   - history text never appears in emitted telemetry events, Sentry report payloads, the Report a problem preview, or log output (captured logs at all levels);
   - the file has mode 0600;
   - no app name, bundle ID or window title is stored.
5. [auto] Settings → History lists entries newest first, with relative time, two-line preview and the "Not pasted" chip. Copy puts the full text on the clipboard; Delete removes one entry. The empty state shows. Everything works by keyboard and has accessible names.
6. [auto] The menu gains "History…" (opens Settings → History). "Copy last dictation" copies the newest entry, or the in-memory one when history is Off.
7. [auto] docs/privacy.md gains a "Dictation history" section stating the rules above, and the website's "Never sent" list stays true. (A site PR follows from the Design Lead if the copy needs it.)
8. [manual] In the VM: dictate 3 times (one with the paste forced to fail), check the list, Copy, Delete, change the limit to 10 and back, then Off. Check the history file's permissions with `ls -l`. Screenshots go on the PR.

## Out of scope

- Search, corrections and editing (#216 later).
- Sync.
- Storing audio.
