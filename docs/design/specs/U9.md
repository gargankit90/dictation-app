# U9: Settings polish (owner's three findings, plus the screenshot-pack review)

> **Built as U12 by the Lead** (the Lead's U9 is setup blockers). Owner decisions in brief-u12.md win where they differ.

Build spec from the Design Lead, 2026-11-04. Small, styling and copy only. The owner found these in the running app on `main`. The sidebar one is my miss: I passed it on contrast without judging how bright it looks.

Design source: docs/design/design-system/tokens.css (five new tokens) and index.html.

## 1. Keychain notice

**Today:** `src/Settings.tsx:343` renders the notice above `{pane}`, so it shows on every section. It uses `.notice.ok`, which is the success green, but the text is advice, not a success.

**Design:**
- Show it **only in the Speech section**, and only when a cloud key is saved. People with no saved key never see the macOS prompt.
- Neutral information style: a rounded box on `--vc-accent-soft` with `--vc-ink` text (13 px, `--vc-radius-md`, `--vc-space-3` padding), no green and no icon.
- Add a **"Got it"** secondary button that dismisses it for good. Otherwise it goes away on its own, as it does today (first launch after the rename only).

## 2. Sidebar selection in dark mode

**Today:** `.settings-sidebar button.selected` fills the row with `--vc-accent`, which in dark mode is the light `#7EA2FF`. Fine for links and small text, too bright as a large fill.

**Design:** two new tokens, already in DS1 tokens.css, to copy to `src/styles/tokens.css` and `site/index.html`:

| Token | Light | Dark |
|---|---|---|
| `--vc-selection-bg` | `#1F4FC9` | `#2F4FA3` |
| `--vc-selection-fg` | `#FFFFFF` | `#FFFFFF` |

White on `#2F4FA3` is 7.6:1. Use them for `.settings-sidebar button.selected`. If U8's rail selection uses its own colour, leave it as it is unless it's equally bright.

## 3. About links

**Today:** `LinkButton` in `src/settings/HelpAbout.tsx` renders underlined blue text, which looks like a web page.

**Design:** native **secondary buttons** (the DS1 28 px button), right-aligned in the row like Help's buttons, with these labels:
- Licence → **"View Licence"**
- Source code → **"Open on GitHub"**
- Credits → **"View Credits"**

Underlined links stay only inside running text (for example the Groq how-to and the language helper line). "Open on GitHub" is the only one that leaves the app; keep whatever it does today for the other two.

## 4. Primary buttons in dark mode

Same problem as the sidebar: the fill is `#7EA2FF`. Three more tokens, already in DS1 tokens.css:

| Token | Light | Dark |
|---|---|---|
| `--vc-primary-bg` | `#1F4FC9` | `#3B6BE0` |
| `--vc-primary-hover` | `#163C9A` | `#3461CF` |
| `--vc-primary-fg` | `#FFFFFF` | `#FFFFFF` |

Use them for `button.primary`, onboarding's primaries and the switch's on state. White on `#3B6BE0` is 4.8:1. Links and small accents keep `--vc-accent`.

## 5. Selected sidebar row's focus ring

A 3 px ring at 2 px offset around a filled row reads as a double border. For the selected row only, draw the keyboard focus ring inset: 2 px white, inside the row. A mouse click must show no ring.

## 6. Own-key panel closed by default

In Speech, the panel is open even when the on-device model is Active, so "Groq API key" falls below the fold. Keep it closed behind "Set up…" (as in DS1), unless own key is the chosen engine and needs a key.

## 7. Provider popup

Make it a normal grouped row: "Provider" on the left, a compact popup on the right (like History's), not a full-width control.

## 8. One line after saving a key

After Test & Save, show only "✓ Connected · saved in Keychain". Show "A key is saved in your Keychain. The key is never shown again." only when a key is already saved and nothing has been tested yet.

## 9. Troubleshoot

- Window title: "Vocet Troubleshoot" while it shows Troubleshoot (U1 criterion 1). Add a way back to Settings if it opens inside that window.
- Move the raw code ("(key_missing)") into a small "Details" disclosure. It stays in the report.
- "Hotkey" → "Dictation key"; "Transcription engine" → "Speech engine".

## 10. One word for the key

Use **"dictation key"** in all user-facing text: the Settings row label (now "Shortcut"), Troubleshoot, and any message saying "hotkey". Analytics names and code identifiers don't change.

## 11. Menu during a download

When an on-device model is downloading and it's the chosen engine, or no engine works yet, the status line is "↓ Downloading <name>, N%" rather than "! No API key saved."

## 12. Update alert (confirm first)

The screenshot pack's notes say "Couldn't check for updates" also appears when Settings opens, and one shot shows two stacked. The code I read doesn't show a path for it. Please confirm on a normal launch. If it's real, fix it: offline users must not get an alert from opening Settings, and alerts must not stack. Either way, when the user presses Check now, show the result inline in the General row instead of a modal with a red stop sign.

## Acceptance criteria

1. [auto] The Keychain notice renders in the Speech section only, and only when a cloud key is saved. It doesn't render in any other section, or when no key is saved (test each).
2. [auto] The notice has no `.ok` or success colour. "Got it" hides it, and it stays hidden after reopening Settings and after a relaunch (test).
3. [auto] `--vc-selection-bg` and `--vc-selection-fg` are in `src/styles/tokens.css` with the values above, and the selected sidebar row uses them. The tokens lint still passes, and the copy of the tokens in `site/index.html` is updated so the "same tokens" test passes.
4. [auto] The About rows use buttons, not `button.link`, with the labels above, and their accessible names match. `button.link` is no longer used in About.
5. [auto] `--vc-primary-*` tokens are in `src/styles/tokens.css` and `site/index.html`; `button.primary` and the switch's on state use them.
6. [auto] Own-key panel: closed by default when another engine is Active; open when own key is chosen and needs a key (test each).
7. [auto] After a successful Test & Save only the "Connected" line shows; a saved key with no test shows only the "A key is saved" line.
8. [auto] Troubleshoot's title says Troubleshoot; the error code is not visible until Details is opened, and stays in the report; labels read "Dictation key" and "Speech engine".
9. [auto] A test fails if "hotkey" or "shortcut" appears in user-facing strings in `src/` or the sentence table (excluding tests and identifiers).
10. [auto] The menu shows the Downloading status per section 11, with a model test.
11. [manual] Window-only screenshots on the PR, in light and dark: Speech with the notice, General without it, the sidebar and About in dark, a primary button in dark, Speech with the panel closed, and Troubleshoot. The Design Lead posts OK or CHANGES.

## Out of scope
