# Design review: running app on main (db99ea8) vs design system DS1

Design Lead, 2026-11-05. Source: the Lead's pack at ~/vocet-screens/main-db99ea8 (78 shots, light and dark). I looked at all 78 shots on contact sheets, at reduced size. 42 were on larger sheets; the other 36 were on smaller ones, as a check that they showed nothing new. So small differences in spacing or type sizes could be missed; nothing was measured pixel by pixel. U8's screenshots (PR #269) were reviewed separately.


## Verdict

We are building the right thing. The app is recognisably the approved design: quiet, native, the Vocet name throughout, tokens in place, and honest about states. The gaps are polish, not direction.

## Matches the design

- **Recording pill:** Listening with the meter and "Release to paste · Esc to cancel"; Transcribing…; "Paste sent" with the green check; error with the amber badge and one plain sentence, no code. Dark in both appearances.
- **Menu bar:** three-bar icon with no text beside it, the attention dot, the recording variant. Light and dark.
- **Menu:** status first, the engine line, the fix row ("Open Speech settings…"), Copy last dictation, then Settings, Troubleshoot, Report a problem, Check for updates, Quit Vocet.
- **Settings:** sidebar sections, grouped rows, instant changes, plain model names, model states (477 MB / ↓ downloading / Loading… / Downloaded / ✓ Active), "! Needs a key", clear inline errors, destructive style on Remove key.
- **Name:** Vocet in every window, menu and message. (The GitHub URL still says dictation-app, which is correct.)
- **Copy:** "→" paths everywhere, and error sentences that name the fix.
- **Old 4-step setup on main:** honest (Finish stays disabled until a real dictation) and replaced by U8.

## Off: already in U9

1. **Dark sidebar selection is too bright.** Confirmed in every dark Settings shot.
2. **About links look like web links.** Confirmed.
3. **Keychain notice on every section in green.** Not in the pack (it only shows on the first launch after the rename); confirmed in the code at `src/Settings.tsx:343`.

## Off: new, add to U9

4. **Primary button fill in dark is too bright** (same #7EA2FF): "Continue", "Test and continue", "Finish", and U8's buttons. New tokens `--vc-primary-bg` / `--vc-primary-hover` / `--vc-primary-fg`: light unchanged (#1F4FC9 / #163C9A / white); dark #3B6BE0 / #3461CF / white. White on #3B6BE0 is 4.8:1, and the fill is 3.5:1 against the window. Use for `button.primary` and the switch's on state.
5. **Heavy ring on the selected sidebar row.** A 3 px ring at 2 px offset around a filled row reads as a double border, in light and dark. Keep a visible focus ring for keyboard users, but draw it inset in white (2 px, inside the row) for the selected row. Check that a mouse click shows no ring: these shots were driven by automation, which may count as keyboard focus.
6. **Own-key panel is open by default in Speech,** pushing the rest down so "Groq API key" is cut off at the fold, even when the on-device model is Active. DS1 has a closed row with a "Set up…" button. Keep it closed by default; open it only when the user asks, or when own key is the chosen engine and needs a key.
7. **Provider dropdown is full-width with an old-style gradient,** and looks heavier than everything around it (History's small popup is right). Make it a normal row: "Provider" on the left, a compact popup on the right.
8. **Two lines say the same thing after Test & Save:** "A key is saved in your Keychain. The key is never shown again." and "✓ Connected · saved in Keychain". Show only the second after a test. Show the first when a key is already saved and nothing has been tested yet.
9. **Troubleshoot window:**
   - The title says "Vocet Settings"; it should say "Vocet Troubleshoot" (U1 criterion 1).
   - The raw code still shows inline: "(key_missing)". U1 said codes live behind Details: move it into a small "Details" disclosure, and keep it in the report.
   - Wording: "Hotkey" → "Dictation key", "Transcription engine" → "Speech engine".
10. **One word for the key.** "Shortcut" (Settings), "dictation key" (setup, errors), "hotkey" (Troubleshoot, setup messages). Use **"dictation key"** in all user-facing text, including the Settings row label.
11. **Menu during a download.** With no key saved and a model downloading, the menu says "! No API key saved." and "Open Speech settings…", though the user is already fixing that by downloading. When an on-device model is downloading and it's the chosen engine, or no engine works yet, show "↓ Downloading …, N%" first.

## Needs confirming, not a design call

12. **"Couldn't check for updates" alert.** The pack's index says it's also raised when Settings opens. The code I read says the launch check is quiet offline (`updater.rs:376`), and I found no path from opening Settings, so I can't confirm it. In `alert-check-for-updates-light.png`, a second copy of the alert sits behind the first, so they can stack. Someone should watch for it on a normal Mac: an offline user must not get a red alert from just opening Settings. Separately, when the user presses Check now, the result should show inline in the General row rather than as a modal with a red stop sign.
