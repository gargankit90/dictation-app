# M0.2: engineering rules, agent definitions and milestone specs

## Goal

Write down how the app is built and how the agents work, before any feature
code, so every agent follows the same rules.

## Scope

- `AGENTS.md`: rules every agent follows (Claude Code and Antigravity read it).
- `CLAUDE.md`: imports `AGENTS.md`, plus notes for Claude Code.
- `docs/ENGINEERING.md`: the plan's best practices, expanded.
- Role instructions: `.claude/agents/developer.md`, `docs/agents/tester.md`,
  `docs/agents/reviewer.md`.
- `docs/review-checklist.md`: the checklist the Code Reviewer works through.
- Specs for every later milestone in `docs/milestones/`.
- Local guards that keep agents off `main` (GitHub Free can't protect
  branches on a private repo): `scripts/guard-push.sh` run by git's pre-push
  hook (`scripts/pre-push`, installed by `scripts/install-hooks.sh`),
  `.claude/hooks/guard-git.sh` and deny rules in `.claude/settings.json`.
- `docs/tech-debt.md`, `test-reports/`, `reviews/`.

## Out of scope

- The quality gate, CI and the signing certificate (M0.3).
- Any app code.

## Acceptance criteria

1. `[auto]` Every file listed in Scope exists.
2. `[auto]` `scripts/guard-push.sh` refuses a push to `main`, a non-fast-forward
   push, deleting a branch and moving a tag, and allows a new branch, a new
   tag and a fast-forward (tested by feeding it pre-push input), and a real
   `git push --dry-run` to `main` is refused once `scripts/install-hooks.sh`
   has run.
3. `[auto]` `.claude/hooks/guard-git.sh` blocks force pushes, pushes to `main`,
   `--no-verify`, disabling hooks and `gh pr merge`, and allows ordinary
   pushes, commits and `gh pr create`.
4. `[auto]` Every milestone in the plan from M0.3 to M-W.3 has a spec with goal,
   scope, out of scope and numbered acceptance criteria tagged `[auto]` or
   `[manual]`.
5. `[manual]` The Lead reads `docs/ENGINEERING.md` and the specs and agrees
   them.
6. `[manual]` Trial run of the PR flow on PR #1 (M0.1): the Antigravity Tester
   and Code Reviewer review it through Orca, post their `Tester:` and
   `Reviewer:` comments, and the Tester merges it.
