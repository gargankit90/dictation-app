# M1.6: hotkey hardening

## Goal

Fix the M1.4 hotkey defects found by the retrospective review (#80).

## Scope

- B1: modifier press/release decided from the event's actual flags (or physical key state), not a toggled remembered bit; a correct initial snapshot when listening starts.
- B2: when the event tap is disabled and re-enabled, or a release is otherwise lost, the adapter reports it and an active recording is cancelled (not transcribed).
- M1: a listener that dies is reported (runtime error to the user via the existing error path) and the adapter can be started again.

## Acceptance criteria

1. [auto] Starting with Right Option held, then releasing, emits no Pressed; the next press/release pair works. Covered for both Option sides and with the other Option held.
2. [auto] Tap disabled (both reasons) with the key down, then re-enabled with no more input: the recording is cancelled, not transcribed (adapter + coordinator/pipeline test).
3. [auto] A listener failure surfaces an error and start() works again afterwards.
4. [manual] In the Lume VM: dictation with Right Option still works end to end (e2e press_release passes; a real hold/release via cua-driver if possible).
