# D1: the repo's front door: README and tester guide

## Goal

The repo is public and linked from the owner's LinkedIn series. A visitor
should see what the app is, its status, how to try it, how it was built, and
how to build it on a clean Mac. Docs only, plus one issue template. Not in
scope: the agent docs (D2) and moving the history (D3). Release links and
wording in `docs/TESTERS.md` (section 1), `docs/releasing.md` and
`docs/ENGINEERING.md` belong to R1.

## Acceptance criteria

1. [auto] README top: a one-line description; a status line (alpha; macOS 13+
   on Apple Silicon only, the DMG is aarch64; cloud transcription with your
   own Groq or OpenAI key; Windows and local models planned); "Try it"
   linking Releases (`https://github.com/gargankit90/dictation-app/releases/latest`)
   and `docs/TESTERS.md`; "How it was built" (a Lead, Developer, Tester and
   Reviewer of AI agents, two model families; links `AGENTS.md`; a link to the owner's LinkedIn profile). A comment
   `<!-- demo GIF goes here -->` with the `docs/media/demo.gif` reference, and
   no fake image.
2. [auto] One ordered Mac quickstart for building: Xcode Command Line Tools,
   rustup, Node 24, the gate tools (with the versions the gate uses), clone,
   `npm ci`, the hook installer, the dev certificate script,
   `npm run tauri dev`. "Requirements" is renamed "Development prerequisites".
3. [auto] The README layout table also explains `scripts/`, `tests/e2e/`,
   `third_party/`, `docs/` and the agents' paper trail (`test-reports/`,
   `reviews/`, `docs/milestones/`; "moving to docs/history/ soon").
4. [auto] `docs/TESTERS.md` (outside R1's lines): Apple Silicon (M1 or newer)
   and macOS 13+; first-run steps follow the onboarding wizard (microphone,
   Accessibility, provider and key, try it) with Settings as the recovery
   path; Groq recommended, OpenAI the alternative; a "Report a bug" section
   linking the issue chooser and saying what to attach.
5. [auto] `.github/ISSUE_TEMPLATE/bug.yml` (macOS version, Mac model, app
   version, steps, expected/actual, log zip) and `config.yml` (SECURITY.md
   for vulnerabilities; blank issues allowed).
6. [auto] The README's CI paragraph is exact: hosted runners for every pull
   request and pushes to main; VM end-to-end tests are run by the maintainer
   locally after each merge (closes #181).
