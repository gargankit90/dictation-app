# T3: bounded operations and combined regression checks

## Goal

Tests (and the fixes they expose) for the hangs, late pastes, leaks and
quiet failures a user could hit, from the follow-up test audit (comment on
#103, "T3" group). Mostly unit and integration tests; little VM time.

## Scope

- **#113 — saving a key can't hang Settings.** A blocked keychain write is
  bounded; Settings shows an error and can retry; no extra thread per retry.
- **#115 (headless part) — quitting during a real request.** A real local
  HTTP request through the pipeline is cancelled at shutdown: no retry, no
  late paste.
- **#121, #122 — launch at login.** An invalid or failed Settings save can't
  change the login item; the native adapter's register/unregister/refusal/
  requires-approval paths are tested through an injected `SMAppService`
  facade (never touching the host's login items).
- **#124 — privacy across threads and files.** Logs from spawned pipeline
  tasks, stderr and rotated files are captured together (with a positive
  control) and contain no key or transcript.
- **#125 — microphone rates.** For uncommon rates, the beginning and the end
  of a finite recording survive resampling (exact counts).
- **#120 — overlay placement.** Physical-to-logical monitor conversion,
  including Retina and mixed-scale monitors, puts the pill on the right
  screen.
- **#129, #130, #133 — single instance.** The singleton's storage can't
  regress to temp files; Quit doesn't wait out a deadline after forwarding
  is done; a second app can't start before shutdown finishes.
- **#110, #112 — overlay follow-ups.** The ACL test checks main can call all
  five app commands and the overlay none; the overlay event channel is
  bounded with the same coalescing policy as #84, with a stalled-consumer
  test.
- **#127, #128, #139 — test hygiene.** Single-instance fixtures leave no
  files behind; failed runs keep the evidence needed to diagnose them
  (bounded, redacted); the flaky named-pasteboard test is fixed.

## Out of scope

- Native VM journeys (T4): the key fixed in the same session (#114), Quit
  during a request in the real app, Esc/busy input (#116), focus switch
  (#117), paste whitespace/Unicode (#118), rendered overlay states (#119),
  launch at login across a second reboot (#123), microphone denial and
  recovery (#126).

## Acceptance criteria

1. `[auto]` Each issue in Scope has a test that fails when its bug is put
   back (show it in the PR for each), and the product fixes those tests
   need.
2. `[auto]` No test uses a sleep as proof; fakes have entered/released
   fences and bounded outcomes.
3. `[auto]` The full gate stays under ~10 minutes; the changed tests pass
   50 times in a row under CPU load.
4. `[auto]` `tests/e2e/run.sh` still passes.

Every milestone also needs: the gate green, coverage at or above thresholds,
`Tester: PASS` and `Reviewer: APPROVED` on the PR.
