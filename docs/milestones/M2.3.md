# M2.3: mic hardening

## Goal

Fix the M2.2 capture defects found by the retrospective review (#77).

## Scope

- B1: before reusing a warm recorder, check that its device is still the current default input; reopen if not. A default-input change during a recording keeps the current recording on the open device (document the policy).
- B2: no capacity/layout mismatch and no allocation on the audio thread from the coreaudio-rs input callback wrapper when the callback frame count changes.
- M1: the final microphone teardown runs off the async executor.
- M2: recorded clip length matches the captured input within 1% (remove the resampler's leading delay, keep the tail).
- #81 (added by the Lead; same audio worker in `crates/app/src/pipeline.rs`):
  - B1: a cancel or shutdown invalidates queued `Start`s of abandoned sessions; at shutdown pending work is dropped and only the one in-flight blocking call plus the final discard finish.
  - M1: the hotkey and audio queues are bounded with a documented overflow/coalescing policy, and a key flood can't starve ticks, audio failures or job results. Bounding the UI queue is a follow-up (#84): its receiver type is named by Tester tests and `src-tauri`.
  - M2: a `PermissionDenied` start that loses the race with the release still surfaces "Microphone permission is missing." Core change: `Transcribing` + `PermissionMissing` now shows the error and returns to `Idle` (it was ignored; M1.1 criterion 3's tests are updated). The pipeline only sends `PermissionMissing` while transcribing for this case, since presses check permissions only when idle.

## Acceptance criteria

1. `[auto]` A default-only route switch while warm (old device still alive) reopens on the new default at the next start (fake opener test).
2. `[auto]` The coreaudio-rs input callback path survives frame-count growth and shrink then teardown without a capacity mismatch (test under the patched crate; Miri or allocator instrumentation where feasible).
3. `[auto]` Holding a slow teardown doesn't stall unrelated runtime work (timer test).
4. `[auto]` Clip length within 1% for 48 kHz and 44.1 kHz inputs of 200 ms and 1 s, counting valid output frames.
5. `[manual]` On a Mac: dictate with the built-in mic, switch the default input within 30 s, dictate again: the new input is recorded.
6. `[auto]` Recordings cancelled while the first `start` blocks never start; shutdown waits only for the call in flight, then discards (#81 B1).
7. `[auto]` A synchronous key flood while a `start` blocks queues at most a bounded number of keys and no audio work for the cancelled recordings; a dropped key cancels the recording; a due Tick isn't held off by keys (#81 M1).
8. `[auto]` A `PermissionDenied` start that finishes after the release shows "Microphone permission is missing." once, and `stop` isn't called on the failed start (#81 M2).
