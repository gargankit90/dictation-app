# M2.3: mic hardening

## Goal

Fix the M2.2 capture defects found by the retrospective review (#77).

## Scope

- B1: before reusing a warm recorder, check that its device is still the current default input; reopen if not. A default-input change during a recording keeps the current recording on the open device (document the policy).
- B2: no capacity/layout mismatch and no allocation on the audio thread from the coreaudio-rs input callback wrapper when the callback frame count changes.
- M1: the final microphone teardown runs off the async executor.
- M2: recorded clip length matches the captured input within 1% (remove the resampler's leading delay, keep the tail).

## Acceptance criteria

1. `[auto]` A default-only route switch while warm (old device still alive) reopens on the new default at the next start (fake opener test).
2. `[auto]` The coreaudio-rs input callback path survives frame-count growth and shrink then teardown without a capacity mismatch (test under the patched crate; Miri or allocator instrumentation where feasible).
3. `[auto]` Holding a slow teardown doesn't stall unrelated runtime work (timer test).
4. `[auto]` Clip length within 1% for 48 kHz and 44.1 kHz inputs of 200 ms and 1 s, counting valid output frames.
5. `[manual]` On a Mac: dictate with the built-in mic, switch the default input within 30 s, dictate again: the new input is recorded.
