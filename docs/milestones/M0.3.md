# M0.3: quality gate, CI and signing certificate

## Goal

Turn on every check from `docs/ENGINEERING.md` so each push and PR is gated, and sign builds with a fixed dev certificate.

## Scope

- lefthook: pre-commit (staged files: `cargo fmt --check`, `prettier --check`, `eslint`, `typos`); pre-push keeps `scripts/guard-push.sh` and adds the full gate.
- Workspace lints in the root `Cargo.toml` (`unwrap_used`, `expect_used`, `dbg_macro`, `todo` denied; `clippy::pedantic` in `core`).
- `deny.toml` (permissive licences only, advisories, duplicates), `cargo machete`, `typos.toml`, nextest config.
- Coverage script using `cargo llvm-cov` with per-crate thresholds (`core`, `transcribe` ≥ 85%, `app` ≥ 70%); crates with no code yet are listed as skipped.
- ESLint (typescript-eslint strict + react-hooks), Prettier, Vitest with one sample test.
- `scripts/test-guards.sh`: runs the push-guard and Claude-hook cases; part of the gate.
- GitHub Actions workflow on `macos-latest` running the same gate on every PR and on `main`.
- `scripts/make-dev-cert.sh`: creates the self-signed `dictation-app Dev` code-signing certificate in the login keychain; Tauri config signs builds with it.

## Out of scope

- Windows CI (M-W.1). Developer ID signing and notarisation.

## Acceptance criteria

1. `[auto]` `lefthook run pre-push` passes on the branch.
2. `[auto]` The CI workflow passes on the PR.
3. `[auto]` On a throwaway branch (never merged), a deliberate clippy warning makes both `lefthook run pre-push` and CI fail. Same for an `unwrap()` in non-test code.
4. `[auto]` `cargo deny check` and `cargo machete` pass; `deny.toml` rejects GPL licences.
5. `[auto]` The coverage script fails when a crate is below its threshold (shown with a temporary low threshold) and passes on the branch.
6. `[auto]` `tsc --noEmit`, `eslint --max-warnings 0`, `prettier --check`, `vitest run` and `typos` pass.
7. `[auto]` `scripts/test-guards.sh` passes and runs in the gate.
8. `[manual]` `scripts/make-dev-cert.sh` creates `dictation-app Dev`; `codesign -dv` on a debug build shows that identity.
9. `[auto]` README and `AGENTS.md` list the gate commands.

Every milestone also needs: the gate green, coverage at or above thresholds, `Tester: PASS` and `Reviewer: APPROVED` on the PR.
