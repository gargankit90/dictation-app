# M1.7: shell hardening

## Goal

Fix the M1.5 shell defects found by the retrospective review (#82).

## Scope

- B1: two near-simultaneous cold launches must not both start (one pipeline, one hotkey listener, the single-instance socket intact).
- M1: Tauri capabilities least-privilege: the UI gets only the permissions it uses (no tray removal/hiding, nothing from core:default it doesn't need).
- M2: an idle local peer on the single-instance socket can't block later launches from forwarding (timeouts, non-blocking accept, bounded reads).

## Acceptance criteria

1. [auto] A race test with two cold launches (or the single-instance logic driven concurrently) ends with exactly one running instance and a working forward path.
2. [auto] The capability files grant only the listed permissions (a test or a lint over the JSON), and the UI still works (Vitest/IPC tests green).
3. [auto] An idle socket peer doesn't delay a second launch's forward beyond a small bound (test with a connected-but-silent client).
4. [manual] In the Lume VM: launching twice quickly leaves one tray icon; Settings still opens; e2e green.
