# T6: VM e2e suite on every merge to the default branch

## Goal

Every merge runs the full VM e2e suite on the owner's self-hosted runner,
so a break in what users see (paste, hotkey, permissions, tray, quit) is
caught the same day even when no Tester re-ran that scenario. The two VMs
stay shared: CI borrows whichever is free through the existing lock.
Owner decision 2026-11-02 on #104.

## Scope

- **A CI job on push to the default branch only** (not on PRs, not
  nightly): a new job or workflow on `[self-hosted, macOS, owner-mac]`
  that runs the VM suite after the build. Non-blocking for now: it never
  turns the default branch red because a VM was busy, and a real scenario
  failure shows as a failed job.
- **VM pool.** A small wrapper (e.g. `tests/e2e/ci-run.sh`) that tries
  `dictation-vm-2` first, then `dictation-vm`, using the existing
  `run.sh` lock; if both are held, wait with a bounded timeout (say 45
  minutes) and then exit as "skipped: no VM free" (job neutral/success
  with a clear summary line, not a failure). Never `dictation-vm-golden`
  or its backups; never start a third VM (macOS allows two running macOS
  VMs). Agents keep their VMs (Developers `dictation-vm`, Testers
  `dictation-vm-2`); they simply wait on the lock while CI holds one.
- **Scenarios.** The full suite except those needing a real key or real
  microphone (`e2e_real_groq`, and `e2e_real_mic` if it needs host audio):
  CI never has an API key. Use T4a's local provider seam.
- **Evidence.** Always upload the per-scenario PASS/FAIL/SKIP summary, the
  tested SHA, the VM used and the logs already collected on failure, with
  bounded retention. No keys or transcripts in artifacts.
- **Docs.** `tests/e2e/README.md` and `docs/ENGINEERING.md`: what runs
  where, how the pool works, how to clear a stale lock. Fix the
  "Not part of CI (CI has no VM)" header in `run.sh`.

## Out of scope

- Running the VM suite on PRs (a later step once flakiness is known).
- A second runner instance or a second Mac (owner decision).

## Acceptance criteria

1. `[auto]` The job runs on push to the default branch only; a PR run
   doesn't start it (shown by the workflow's triggers and a PR's checks).
2. `[auto]` The wrapper picks a free VM, prefers `dictation-vm-2`, waits
   while both are locked and exits "skipped: no VM free" after the
   timeout; shell tests with fake locks prove each case and that it never
   names the golden image.
3. `[auto]` The suite excludes real-key/real-mic scenarios and passes on a
   real run through the wrapper on this Mac (run it locally the way the job
   does; paste the summary in the PR).
4. `[auto]` On failure the artifact holds the per-scenario summary, SHA,
   VM name and logs; a deliberately failing scenario in a local dry run
   proves the collection step (don't push a failing scenario).
5. `[auto]` The docs and the `run.sh` header describe the CI job and pool.

Every milestone also needs: the gate green, coverage at or above
thresholds, `Tester: PASS` and `Reviewer: APPROVED` on the PR.
