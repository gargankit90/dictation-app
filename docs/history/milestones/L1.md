# L1: On-device transcription with a downloadable local model

Part of #207.

## Goal

Owner decision 2026-11-03: transcription = local models AND bring-your-own-key;
no paid plan. Start with Parakeet Unified EN 0.6B (Q4_K_M, ~477 MB) on the
transcribe-cpp crate; offer Qwen3-ASR 0.6B (Q4_K_M, ~590 MB, includes Hindi)
as the second model. The owner's evals may change the default later, so the
model list is data, not code paths.

## Acceptance criteria

1. [auto] A local engine in crates/transcribe (behind the existing
   transcriber port) runs a GGUF model through transcribe-cpp on 16 kHz mono
   audio and returns text. Unit-testable without the real model (port fake);
   one integration test with a tiny model or a skipped-unless-present real
   model.
2. [auto] A model catalogue (data file or const table): id, display name,
   languages, size in bytes, download URL (Hugging Face, pinned revision),
   SHA-256. Exactly the two models above for now; the first is the default.
   Verify the real URLs, sizes and hashes; never invent them.
3. [auto] Model manager: download to
   ~/Library/Application Support/<app>/models/ with progress events, resume
   after interruption, SHA-256 verification before use, cancel, delete,
   disk-space check before starting. Errors are typed (no space, network,
   checksum, cancelled). Tests with a local HTTP fake.
4. [auto] Settings: engine choice "On this Mac" (pick a model,
   download/delete, see status) vs "Your own key" (existing Groq/OpenAI).
   Saved in settings; LiveEngine rebuilds on change. A local engine whose
   model isn't downloaded is Unavailable with a clear message and next step
   ("Download the model in Settings").
5. [auto] Dictation with the local engine goes through the same pipeline
   (overlay states, paste, errors) as the cloud engines; no audio written to
   disk outside debug mode; no transcripts at info level.
6. [auto] Load the model once and keep it warm while the engine is selected;
   release it when switching away. Transcription runs off the event loop.
7. [auto] CI: the hosted Linux and macOS jobs build with the new C++
   dependency (CMake/toolchain steps in the workflows if needed); the gate
   passes; cargo deny/licences pass; NOTICE credits transcribe.cpp/Handy as
   used.
8. [manual] In the VM (E2E_VM=dictation-vm-2 via tests/e2e/run.sh, or
   dictation-vm when free): download the default model, dictate into
   TextEdit offline (network off if feasible), text is pasted. Note
   release-to-text latency on the VM and on the host build.

## Out of scope

Onboarding redesign (separate milestone; keep the current onboarding
working: if the local engine is selected, the key step is skipped or says no
key needed), streaming/partial results, VAD tuning, Intel-specific tuning.
