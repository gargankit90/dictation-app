# U6: Settings in sections, changes applied instantly, clear model states

Build spec from the Design Lead, 2026-11-03.
- **Depends on:** S1 (#238, launch at login applies in the background) and U2 (language picker).
- **Design:** ~/Documents/dictation-design/design-system/index.html, the "Settings rows" section.
- **Styling:** ships in today's settings.css palette if U3 hasn't landed (layout and behaviour are what matter here); restyle in U3.

## Why

Settings is one long 480×640 form with a global Save, mixing four save behaviours:
- engine, shortcut and login need Save;
- downloads start at once;
- analytics changes at once;
- testing a key doesn't save it.

"Downloaded" vs "selected" vs "active" is unclear. (Claude 6; Codex 7 and 8.)

## Design

- **Window:** "Vocet Settings", native title bar, about 720×520, resizable, minimum 640×460.
- **Sidebar** (~170 px, grouped background, selected row in accent) with sections. Each section is a scrolling pane of **grouped rows**: label and caption on the left, control on the right.
- Remember the last section opened; ⌘, opens Settings.

| Section | Rows |
|---|---|
| **General** | Open Vocet at login (switch; shows "Applying…" while S1's background apply runs, then the real state or an inline error) · Check for updates (button + last checked) |
| **Dictation** | Shortcut (HotkeyRecorder) · Language (U2 picker) · Microphone: the input in use ("MacBook Pro Microphone") + "Test microphone" showing U4's level meter inline for 5 s. Selecting a different input device only if the platform already supports it; otherwise show the system device and "Change in System Settings → Sound". |
| **Speech** | Engine list, one row per option. Exactly one is **Active**. On-device models (Parakeet English; Qwen3-ASR multilingual) and Your own key (Groq / OpenAI). Model rows show the state machine below. The own-key row opens an inline panel: provider, a 3-step "Get a key" how-to with a link, a key field, **Test & Save** (only saves if the test passes; shows "✓ Connected · saved in Keychain" only after both), Remove key. |
| **Privacy** | "Share usage and error events" switch (instant) · "What's sent" disclosure (from docs/privacy.md) · a link to the full list |
| **History** | Added by U7 (leave the section out until U7, or show "Coming soon"; Developer's choice, say which in the PR) |
| **Help** | Troubleshoot… · Report a problem… · Show log file · Run setup again |
| **About** | Vocet version, licence (MIT), GitHub link, credits (NOTICE) |

**Model state machine** (shown as a chip plus one action):

| State | Chip | Action |
|---|---|---|
| Not downloaded | "477 MB" (real size from the catalog) | Download |
| Downloading | "↓ 212 of 477 MB" + progress | Cancel |
| Paused / failed | "Paused: no connection" / "Download failed" | Retry |
| Downloaded, not active | "Downloaded" | Use this |
| Loading | "Loading…" | none |
| Active | "✓ Active" (green) | none (another row's "Use this" switches) |
| Error after load | "! Couldn't load" | Retry · Delete |

Every model row has a "Delete" in a "…" menu (not on the active one; to delete the active model, switch first).

**Instant apply:** every control saves on change and shows a brief inline "Saved" (or an inline error next to the control). There is **no global Save button**. Operations with their own lifecycle keep their own buttons: Download, Use this, Test & Save, Record shortcut, Remove key. Closing the window never loses a valid change.

## Acceptance criteria

1. [auto] Settings opens at about 720×520 with the sidebar sections above; ⌘, opens it; it remembers the last section. Keyboard navigation moves between sidebar and pane, and every control has an accessible name.
2. [auto] There is no global Save. Each preference persists on change (tests per control: shortcut, language, launch at login, events switch). Closing and reopening shows the saved values.
3. [auto] The launch-at-login switch shows "Applying…" while the background apply runs and never blocks the window. On failure it reverts to the real OS state and shows the error inline (uses S1).
4. [auto] The Speech section shows exactly one Active engine. Model rows follow the state machine (a test per state, using fake download/load events). "Use this" switches the active engine only after the model reports ready; until then the previous engine stays active.
5. [auto] Own key: Test & Save calls the provider test, then saves to Keychain. The success message appears only if both succeed. A Keychain failure after a good test is its own error ("Key works, but couldn't be saved to your Keychain"). The key is never shown back.
6. [auto] Dictation → Test microphone shows the live U4 meter for 5 s and a "No sound" message if silent. (If U4 isn't merged yet, ship the row without the meter and say so in the PR.)
7. [auto] Help → Show log file replaces the tray's "Reveal log" (U5). Help → Run setup again opens onboarding.
7b. [auto] Every user-facing string that says "Settings → Transcription" (from U1's error sentences and helper lines) says "Settings → Speech" once the section exists. A test fails if "Settings → Transcription" remains.
7c. [auto] K1's typed fallback ("Or type it", e.g. `RightAlt`) is removed from Settings, or moved behind a small "Type a shortcut instead" disclosure that shows keycap names, not raw syntax.
8. [auto] Existing Settings tests are migrated. The VM scenarios e2e_settings_save_reopen and e2e_settings_key_provider_recovery are updated for instant apply and still pass.
9. [manual] In the VM, in light and dark mode: each section; a model download from "477 MB" to "✓ Active"; a bad key shows its inline error; and toggling launch at login never freezes the window. Screenshots go on the PR.
