# D3: The agents' paper trail moves to docs/history/

Owner-approved 2 Nov 2026. `test-reports/`, `reviews/` and `docs/milestones/`
(about 250 files, 13 MB, mostly screenshots) sit at the repo root and look like
product folders. They are the record of how the agents built the app, so they
stay, under one guided folder. Links in LinkedIn posts are pinned to the `pub2`
tag, so moving files on the default branch breaks none of them.

1. [auto] `git mv` in a rename-only commit (no content changes in it):
   `docs/milestones/` to `docs/history/milestones/`, `test-reports/` to
   `docs/history/test-reports/`, `reviews/` to `docs/history/reviews/`.
   `git log --follow` keeps the history.
2. [auto] `docs/history/README.md`: what these are (each milestone's spec with
   numbered acceptance criteria, each Tester run, each Code Review round), how
   they connect (milestone id to spec, `test-reports/<id>-run<k>.md`,
   `reviews/<id>-round<k>.md`, the PR), a short table of 6 to 10 of the most
   interesting ones to read first, and one line on the agent team linking
   `AGENTS.md`. Plain and short.
3. [auto] Every reference to the old paths is updated: `AGENTS.md`,
   `CLAUDE.md`, the role files, `docs/review-checklist.md`, `README.md`,
   `CONTRIBUTING.md`, scripts, tests, CI workflows and tool configs. Links
   inside the moved files that point at each other or at repo files still
   resolve, and a link-check script proves it.
4. [auto] New work goes to the new place: a Tester writes
   `docs/history/test-reports/<id>-run<k>.md`, a Reviewer
   `docs/history/reviews/<id>-round<k>.md`, the Lead
   `docs/history/milestones/<id>.md`; the role files say so.
5. [auto] The gate passes and nothing else changes.
