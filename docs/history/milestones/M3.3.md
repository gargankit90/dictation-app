# M3.3: secrets, settings and the API-key command

## Goal

Store the API key safely and persist settings.

## Scope

- `platform::secrets` with the `keyring` crate (Keychain); `MemSecretStore` in tests.
- `core::settings`: model, defaults, validation, schema version and migrations; unknown fields tolerated.
- Settings store (file in the app config dir); never contains the key.
- Tauri commands via `tauri-specta`: `set_api_key` (write-only), `has_api_key`, `get_settings`, `save_settings`.

## Out of scope

- Settings UI (M3.4).

## Acceptance criteria

1. `[auto]` Settings defaults, validation, v1 → v2 migration and unknown fields are unit tested.
2. `[auto]` No command returns the key; the generated TS bindings contain no getter for it.
3. `[auto]` `secrets` tests with the in-memory store; one `#[ignore]` test against the real keychain.
4. `[manual]` Run the ignored keychain test once on the Mac; the item appears in Keychain Access under the app's service name.

Every milestone also needs: the gate green, coverage at or above thresholds, `Tester: PASS` and `Reviewer: APPROVED` on the PR.
