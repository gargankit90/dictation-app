# U4: Recording pill v2 with a real microphone level meter

Build spec from the Design Lead, 2026-11-03. Highest-value item tonight, with U5. Design: ~/Documents/dictation-design/design-system/index.html, the "Recording pill" section. Until U3 lands, implement the pill's own colours directly in `src/overlay/overlay.css` using the DS1 values below; the pill is dark in both appearances, so it doesn't depend on the theme.

## Why

Today's pill says "Recording" with a decorative dot, so it confirms recording, not hearing. A silent or wrong microphone looks the same as a working one (both reviews; Codex problem 9). The owner asked for a real level meter.

## Design

- **Placement and behaviour:** unchanged. A non-activating panel at bottom centre that never takes focus (`e2e_overlay_focus` must still pass).
- **Capsule:**
  - 40 px tall, fully rounded, background `rgba(28,27,25,0.92)` with backdrop blur, white text, shadow `0 12px 32px rgba(28,27,25,.18)`.
  - Label 15 px semibold. Hint 12 px medium in `#C9C6BF`.
- **States:**

| State | Content |
|---|---|
| Listening | red dot `#E5484D` · **7-bar meter** (3 px wide bars, 2 px gaps, 4–18 px tall, white) · "Listening" · hint "Release to paste · Esc to cancel" |
| No sound (level below the silence threshold for 1.5 s while listening) | dot · meter in idle colour `rgba(255,255,255,.28)` · "No sound" · hint "Check your microphone" (if the input device name is known: "Check your microphone (MacBook Pro Microphone)"). Goes back to Listening as soon as level returns. |
| Transcribing | spinner · "Transcribing…" (unchanged) |
| Pasted | green check `#4CC26A` · "Pasted", shown for ~800 ms after a successful paste, then hidden |
| Error | amber "!" badge `#F2B544` on `#1C1B19` · **one sentence** (from U1) · hint "Fix it from the menu bar" once U5 lands (until then no hint) |

- **Meter:** driven by real input level, not animation. Each bar shows a recent level sample (scrolling right to left) or a smoothed band of the current level; either is fine as long as silence looks flat and speech visibly moves the bars.
  - About 20 updates per second.
  - Map RMS to dBFS, about -60 dB → 4 px and -10 dB → 18 px.
  - With Reduce Motion on, update without easing transitions.
- **Accessibility:** the pill keeps `role="status"`; the label text carries the meaning, and the meter is `aria-hidden`. Don't announce level changes. "No sound" is announced once.

## Acceptance criteria

1. [auto] The audio capture (`crates/platform`, the Collector sink) computes an input level per chunk (RMS, or peak; documented) and the pipeline publishes it while recording at ≥15 and ≤30 updates per second. No level is computed or sent when not recording. Unit tests use the fake audio source: silence gives a level at the floor; a sine at -20 dBFS gives the expected level ±2 dB.
2. [auto] Levels reach the overlay over the existing overlay channel (not the webview polling). Levels are never logged at info level, never stored and never sent as analytics. Audio still stays in memory (privacy rule).
3. [auto] The overlay renders the 7-bar meter from the level (a test feeds levels and checks the bar heights), the "Listening" label, and the "Release to paste · Esc to cancel" hint. With `prefers-reduced-motion` there are no CSS transitions on bars.
4. [auto] After 1.5 s of level below the threshold while listening, the pill shows "No sound" with "Check your microphone" (plus the device name when the platform knows it); it returns to Listening when level comes back. The threshold is a named constant with a comment on how it was chosen. Tests use a fake clock.
5. [auto] After a successful paste, the pill shows "Pasted" with a check for 800 ms (±100), then hides. Not shown when the paste failed or nothing was pasted.
6. [auto] The error state shows only the one-sentence message (no code; U1) and the amber badge. The overlay never contains buttons or links (it stays non-activating).
7. [auto] Existing overlay tests still pass (updated for the new markup), and so does `e2e_overlay_focus`: the panel never takes focus or key status.
8. [manual] In the VM, with the virtual sound device:
   - Speaking (`say`) moves the meter, and silence goes flat, then shows "No sound" after about 1.5 s.
   - A paste shows "Pasted" briefly, and a bad key shows the one-sentence error.

   A short screen recording or screenshots of each state go on the PR.

## Notes

- Esc already cancels (Escape is reserved in `hotkey_spec.rs`). If it doesn't cancel during listening today, say so in the PR and drop "Esc to cancel" from the hint rather than adding cancel logic here.
- Restyle in U3: once tokens exist, swap the literal colours for `--vc-overlay-*`, `--vc-recording` and `--vc-meter*`.
