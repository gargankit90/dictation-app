# U8: Five-step onboarding

Build spec from the Design Lead, 2026-11-03. Closes #210.
- **Depends on:** U1 (honest Try it), U2 (language names), U4 (level meter), U6 (model states, own-key panel).
- **Design source:** the round-2 A2 boards on the canvas (canvas-source/project/OnboardingA2*.dc.html), changed per the owner's decisions and Codex's A2 critique (codex-app-ux-opinion.md §3).
- **Styling:** today's palette if U3 hasn't landed; restyle in U3.

## Owner decisions

- 5 steps: **Welcome → Speech → Permissions → Try it → Ready**.
- The local model is recommended; own key is the alternative.
- Usage/error events are on by default, with the switch on the first screen.

## Window and layout

- "Set up Vocet", native title bar, about **740×560**, minimum 680×520.
- A slim left rail (~150 px) with the 5 step names and their state (✓ done / current / upcoming; "Download running" under Speech while it runs).
- The content area scrolls. A fixed footer holds **Back** (left), a reason line when the primary action is disabled ("Continue unlocks when both are allowed"), and the **primary action** (right, 44 px).
- **A persistent download strip** above the footer while a model downloads: "Downloading Parakeet English · 212 of 477 MB · Cancel".
- No fake window controls; real chrome only.
- Closing the window or quitting resumes at the same step next launch ("Resume setup…" in the U5 menu). Choices, the events switch and a partial download are kept, **only as far as implemented**: if a download can't resume across a restart, it restarts and the strip says so.

## Steps

1. **Welcome.** "Talk instead of type": hold Right ⌥, speak, release, and the text lands at your cursor.
   - **Share usage and error events** switch, **on**. Caption: "Anonymous usage events (with a random install ID) and error reports help us fix what breaks. Never audio, transcripts, typed text, keys or app names." Plus a "What's sent" link and "Change any time in Settings → Privacy".
   - **No event is sent before the user leaves this screen**, and none if they switch it off here.
   - Primary: Continue.
2. **Speech.** "Which language will you mostly speak?" (U2 names: English, Hindi, more… with search), then the engine:
   - **Recommended for your language** (preselected): English → Parakeet English (real size); Hindi or other → the multilingual model (real size from the catalog). Copy: "Runs on this Mac. Works offline after a one-time download."
   - Below it, plainly: **Use my own Groq or OpenAI key**, which opens U6's own-key panel inline (how-to, field, Test & Save).
   - Primary: "Download and continue", which starts the download and moves on. For own key: Continue unlocks after Test & Save succeeds.
3. **Permissions.** Two cards, explained before the macOS prompt: **Microphone** ("Records only while you hold your key") and **Accessibility** ("Notices your key and pastes at your cursor. It doesn't read your screen").
   - Each card: Allow → "Waiting for macOS…" → "✓ Allowed", detected automatically. Denied → "Open System Settings" + the exact path. Granted but not applied → "Relaunch and resume" (keeps choices).
   - After the mic is allowed, the card shows the **live U4 meter** and the input name ("Say something: the bars should move"), and "No sound? Check System Settings → Sound".
   - Continue unlocks when both are allowed.
4. **Try it.** "Your dictation key" (HotkeyRecorder, Right ⌥ by default), then a focused practice box: "Click the box, hold the key, say a sentence, let go."
   - Stage line, each part driven by real events only: **Heard you** (level above threshold during the hold) → **Transcribed** (non-empty result) → **Pasted** (the result landed in the practice box).
   - Waits for the model: if it's still downloading, the box says "Getting the model ready: 82%" and the key is disabled for practice.
   - Failures shown inline with one fix: no sound → mic help; key rejected → back to Speech; nothing pasted → the words are shown with **Copy**, plus "Click the box and press ⌘V", never re-pasted automatically.
   - Primary: Continue (enabled after a real success). Secondary: "Skip for now".
5. **Ready.** A summary with real states:
   - Key "Right ⌥ (hold)".
   - Speech "On this Mac · Parakeet English · ✓ Ready" (or "Groq · ✓ Connected").
   - Usage and error events "On · Change".
   - History "Keeps your last 25 dictations on this Mac · Change".
   - "Find Vocet in the menu bar", with an arrow toward the menu-bar icon.
   - "Open Vocet when I log in" switch, **off**.
   - If Try it was skipped: "Not tested yet: try it from the menu bar any time".
   - Primary: "Start dictating" (closes the window).

## Acceptance criteria

1. [auto] Onboarding has exactly these 5 steps, with the rail, the scrolling content and the fixed footer at about 740×560. It works at the 680×520 minimum with the longest Hindi labels (test with pseudo-long strings). Every step has Back (except Welcome) and one primary action; a disabled primary always shows its reason.
2. [auto] Welcome shows the events switch on by default. Telemetry emits nothing until the user continues past Welcome with it on, and nothing at all if they switch it off there (a test with the fake telemetry port).
3. [auto] Speech preselects the recommended model for the chosen language (English → Parakeet English; Hindi → multilingual). "Download and continue" starts the download and advances. The strip shows real progress and Cancel on every later step. The own-key path uses U6's Test & Save and unlocks Continue only after it succeeds.
4. [auto] Permissions: cards explain before prompting, detect grants automatically, and handle denied and needs-relaunch states. Relaunch resumes at Permissions with choices kept. The mic card shows the live meter after the grant.
5. [auto] Try it's stage line is driven by real pipeline events (level, transcription result, paste into the practice box); typing never advances it (extends U1 criterion 6). While the model isn't ready, practice is blocked with progress shown. A failed paste shows the words with Copy and is never re-pasted automatically. "Skip for now" leads to Ready with "Not tested yet".
6. [auto] Ready shows the real states for key, engine readiness, events, history limit (from U7, or omitted if U7 isn't merged) and launch at login (off). "Start dictating" closes onboarding and marks setup complete, so "Resume setup…" disappears from the menu.
7. [auto] Quitting at any step and relaunching resumes at that step. A partial download resumes if supported; otherwise it restarts and says so (no claim the code doesn't back).
8. [auto] Existing onboarding tests are migrated. The VM scenarios e2e_onboarding_first_run and e2e_microphone_denied_then_recover are updated, and a new VM scenario walks all 5 steps with the local model and a real `say` dictation.
9. [manual] In the VM, in light and dark mode:
   - the full English/local path, the Hindi path, and the own-key path with a bad key, then a good one;
   - mic denied, then recovered;
   - quit mid-download and resume;
   - a failed paste in Try it.

   Screenshots of each step and state go on the PR.

## Out of scope

- New colours (U3).
- Sibling products.
- An account (there is none).
