# A2: crash and error reporting with Sentry, and release builds that carry the telemetry keys

Issues: #208 (analytics), #221 (owner to-dos). Time-box: 3 hours to an open PR.

## Spec

Owner decisions: usage analytics (PostHog US, A1) and error/crash reports
(Sentry) are ON by default, governed by the SAME switch (Settings → Privacy,
"Share usage and error events"). Never audio, transcripts, typed or clipboard
text, API keys, app names/window titles, file paths, usernames.

Acceptance criteria:

1. [auto] Spike first (time-box 45 min): can Sentry capture Rust panics AND
   native crashes (e.g. inside the transcribe-cpp C++ engine) from our Tauri
   app on macOS, with a maintained crate/plugin? Record findings in the spec
   file. If native crash capture isn't reliable, ship Rust panic + error
   capture now and file an issue for native crashes.
2. [auto] A Sentry adapter behind the existing Telemetry port (or a sibling
   ErrorReporter port), initialised only when (a) a DSN is present at build
   time (env DICTATION_SENTRY_DSN) and (b) the sharing switch is on. Keyless/
   DSN-less builds and forks send nothing.
3. [auto] Scrubbing before anything leaves the process: send_default_pii off;
   no breadcrumbs from logs or UI; strip file paths to crate-relative frames;
   drop exception messages unless they are E1 error codes / A1 error types; no
   user, IP, hostname or device name; release = app version, environment =
   channel. A test plants secrets/text/home paths in a panic message and an
   error chain and asserts the serialised event contains none of them;
   mutation-check it.
4. [auto] Turning the switch off stops Sentry immediately (close/disable
   client, drop queued envelopes); on again re-enables. Tests.
5. [auto] scripts/release.sh: before building, read DICTATION_POSTHOG_KEY and
   DICTATION_SENTRY_DSN from the owner's Keychain (generic passwords, e.g.
   service names dictation-app-posthog-key and dictation-app-sentry-dsn, same
   pattern as the updater key) and pass them to the build; if missing, warn
   clearly and build without telemetry (don't fail the release). Document the
   two `security add-generic-password` commands for the owner in the release
   doc. Never print the values.
6. [auto] docs/privacy.md and the What's sent list in Settings mention error
   reports (Sentry, US region) and what they contain.
7. [auto] Gate passes; cargo deny passes for new crates.

Out of scope: dashboards, alerting, onboarding redesign.

## Spike findings (2026-11-03)

Tried in a scratch crate outside the repo (sentry 0.49.5 + sentry-minidump
0.49.5, macOS 15 arm64, a local HTTP listener as the DSN):

- **Maintained crates exist.** `sentry` and `sentry-minidump` are both
  getsentry's, MIT, same 0.49.5 release (2026-10). The community
  `tauri-plugin-sentry` (0.8, "experimental") wraps the same idea and adds a
  webview bridge we don't want; `sentry-rust-minidump` is deprecated.
- **Rust panics:** captured by the `panic` feature (a panic hook).
- **Native crashes:** `MinidumpIntegration` re-executes the app binary as a
  crash-reporter process; a deliberate bad write in the app process produced a
  `fatal` event plus a 160 KB `event.minidump` attachment at the listener. So
  capture works on macOS.
- **But the dump is not scrubbable and not private.** The minidump holds raw
  thread stacks and the process environment. The planted string
  `TRANSCRIPT-SECRET…` (a local on the stack) was found inside the uploaded
  dump, as were `USER`, `HOME`, `PATH` and other variables with the user name
  and paths; the event also carried the host name (`server_name`).
  `before_send` cannot edit the attachment. That breaks "never transcripts,
  paths or usernames", and a stack can hold dictated text or a key while a
  transcription runs.
- Symbolication needs `sentry-cli` debug-file upload with an auth token, which
  agents don't hold.

**Decision:** ship Rust panic and error capture now, with an allow-list
scrubber that builds the event from scratch. Native crashes are not captured
in A2; a follow-up issue covers a design that sends no memory (for example a
crash marker on next launch, or a scrubbed dump) plus symbol upload.
