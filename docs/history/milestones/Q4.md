# Q4: New local defaults: OrukQwen 1.7B speech + Gemma 4 E2B cleanup

Owner decision, 2026-11-20: switch the on-device defaults to the eval winners. Evidence: PR #331
(`eval/asr-screen/REPORT.md` on branch `eval/asr-screen`) and PR #326 (`eval/local-cleanup`):

| Local pipeline | ZER Claude / Codex | Download | Speed (median / p90, summed stages) |
|---|---|---|---|
| Parakeet 0.6B (today's default), raw | 53.0 / 49.0 | ~0.5 GB | — |
| **OrukQwen 1.7B Q4_K_M + Gemma 4 E2B (prompt v3)** | **76.8 / 74.2** | 1.32 + 3.1 = **4.43 GB** | **0.93 s / 2.33 s** |
| Voxtral Mini 3B + Gemma (tie, bigger) | 76.8 / 75.5 | 6.09 GB | 1.83 / 3.16 s |

OrukQwen-ASR is Apache-2.0 (https://huggingface.co/oruk/orukqwen-asr-1.7b), English-tuned, and doesn't
output casing/punctuation itself: Gemma cleanup supplies them. Gemma 4 E2B is Apache-2.0.

## Scope

1. **Speech**: add OrukQwen 1.7B Q4_K_M to the local catalogue (`crates/core/src/local_models.rs`) as the
   only local speech model, run through transcribe.cpp the way PR #331's screen ran it (same model file, pinned
   Hugging Face revision, verified size and SHA-256; never invent URLs or hashes). Remove Parakeet and
   Qwen3-ASR (owner, 2026-11-20). No migrations: an unknown saved model id falls back to OrukQwen.
2. **Cleanup**: a local cleaner running Gemma 4 E2B (Q4_K_M GGUF) via llama.cpp, with the prompt and
   settings PR #326 used for its 76.8 result (`eval/local-cleanup` on that branch: prompt v3, sampling,
   context and output caps). Implement it behind the **Cleaner port that Q2 adds** (see
   `docs/history/milestones/Q2.md` §1, being built in parallel on branch `mQ2-cleanup-openrouter`): build
   the llama.cpp runner and model manager first; wire it into the port once Q2 merges (merge origin/main
   in), reusing Q2's guard, deadline and raw-text fallback. Don't edit Q2's files before then.
3. Gemma is a separate download (≈3.1 GB) through the existing model manager (progress, resume,
   checksum, delete, disk check). Keep it warm while selected; release on switch; a timeout stops
   inference so it can't stall the next dictation.
4. Gemma is the cleanup default on every Mac (no rule-based cleaner, no 8 GB branch; owner wants minimum
   complexity). The 8 GB measurement in criterion 5 is recorded for a later decision.
5. Settings → On this Mac: shows speech model and cleanup model with sizes; "Private: nothing leaves this
   Mac". Onboarding for a fresh install downloads OrukQwen + Gemma (≈4.4 GB) with clear progress, and the
   first dictation needs no key.
6. NOTICE / THIRD-PARTY-LICENSES credit llama.cpp (MIT) and the model licences.

## Acceptance criteria

1. [auto] Catalogue tests: OrukQwen is the only local speech model, verified hash and size.
2. [auto] Local cleaner tests with a fake runner: cleaned text used; timeout/error/guard → raw text;
   cancelled inference doesn't block the next job.
3. [auto] Parakeet and Qwen3-ASR are gone (grep); an unknown saved model id loads as OrukQwen.
4. [auto] Gate passes, including licence checks and macOS CI build with llama.cpp.
5. [manual] Lead, in the VM and on the host: dictate with OrukQwen + Gemma; record key-up-to-paste p50/p95
   and peak memory on a 16 GB and an 8 GB configuration (VM memory setting); decide the 8 GB default.

Developer: Opus 5.5 (native inference, platform work). Time box: 1.5 days; progress report at halfway.
