# M3.4: settings UI and Test key

## Goal

Let a tester enter their key, pick a provider and test it.

## Scope

- Settings window: provider (Groq/OpenAI), API key (write-only field), hotkey, language.
- "Test key" button: a tiny request through the real provider; shows success or a clear error.
- Typed commands only; strict CSP unchanged.

## Out of scope

- Onboarding (M5.2).

## Acceptance criteria

1. `[auto]` Vitest: the key form validates input; Test shows success and failure (mockIPC).
2. `[auto]` Vitest: settings save and reload.
3. `[auto]` The key is never rendered back into the UI after saving.
4. `[manual]` With a real Groq key, Test shows success; with a wrong key, a clear error.

Every milestone also needs: the gate green, coverage at or above thresholds, `Tester: PASS` and `Reviewer: APPROVED` on the PR.
