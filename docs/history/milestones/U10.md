# U10: The sharing choice moves to Ready, and setup is measured from the first screen

Spec from the Lead, 2026-11-05.

## Owner decisions, final

- The switch moves from Welcome to Ready. Welcome has no consent card and no notice line about data. The owner considered and declined a notice line.
- Events are collected from the first screen, because the owner needs to know where and why people drop out of setup. This reverses U8 criterion 2 and "Nothing before you choose" in `docs/privacy.md`. Don't reintroduce a hold on sending.

## Acceptance criteria

1. [auto] Welcome has no sharing switch or caption. Ready has the only setup switch, on by default, with the "What's sent" disclosure.
2. [auto] A fresh install makes the install ID and sends setup events from the first screen, with the fake telemetry port proving it. The events show each step reached and where someone stopped, including someone who quits before Ready.
3. [auto] A stored choice wins: if sharing is already off, for example an existing user or Run setup again, nothing is sent at any step, and no install ID is made.
4. [auto] Add drop-off reasons as fixed values in the closed `Event` enum in `crates/ports`, sent from Rust only: download failed, key test failed, permission denied (naming which one) and paste missed, plus others found in the setup steps. They carry no free text: no paths, app names, typed text, transcripts, key material or provider responses. Add each one to the list in `docs/privacy.md`, because the page must list everything sent.
5. [auto] Off on Ready behaves like Off in Settings: sending stops at once, anything waiting is deleted, requests under way are dropped, and the install ID is deleted. A test covers turning it off, including immediately before Start dictating. Keep the single write queue in `src/settings/sharingQueue.ts` and the exit guard.
6. [auto] Error reports follow the same switch, as they do today, and the sharing tests cover them.
7. [auto] `docs/privacy.md` says what really happens: on by default; during first setup, anonymous usage events and error reports are sent from the first screen; the switch is on the last setup screen and in Settings → Privacy; Off deletes what's waiting and the install ID but can't recall what was already sent. Remove "Nothing before you choose". The app's "What's sent" text must not contradict this. Change or remove the U8 tests that enforced the old rule, and say in the PR which and why.
