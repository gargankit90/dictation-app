# A1: Privacy-safe product analytics (PostHog)

Part of #208.

## Goal

Owner decisions 2026-11-03: analytics ON by default with an off switch;
PostHog Cloud US (the owner changed this from EU later on 2026-11-03); Sentry for crashes comes in a separate milestone (A2). The
old rule "No analytics or telemetry" was an agent default, not the owner's;
this milestone replaces it with explicit rules.

## Acceptance criteria

1. [auto] A telemetry port in crates/ports (`Telemetry` trait: record an event
   with a typed, closed set of properties) with a fake for tests; a PostHog
   adapter sending from Rust (not the webview) to the US endpoint
   (https://us.i.posthog.com), batched, off the event loop, bounded queue,
   drops silently on failure (never retries forever, never blocks dictation).
2. [auto] Events are an enum, not free-form strings. Initial set:
   app_opened {version, macos_major, arch}; onboarding_step_reached /
   onboarding_completed {step}; engine_selected {kind: local|cloud,
   model_id|provider}; dictation_finished {engine kind, duration_bucket,
   latency_bucket}; dictation_failed {error_type}; setting_changed {setting
   name only}; update_installed {from_version, to_version}. Property values
   are enums or buckets, never user text.
3. [auto] Never sent: audio, transcripts, typed or pasted text, API keys, app
   names/bundle IDs/window titles, file paths, hostnames, usernames. A test
   plants secrets/text in every pipeline input and asserts no serialised
   event contains them (and no key-shaped strings).
4. [auto] Identity: a random install ID stored locally (not derived from
   hardware), sent as PostHog distinct_id; PostHog person profiles off
   ($process_person_profile=false); IP capture disabled on our side ($ip not
   sent; document that the PostHog project must also discard IPs). Reset ID
   when analytics is turned off and on again.
5. [auto] Settings → Privacy: "Share anonymous usage events" toggle, on by
   default; turning it off stops sending immediately and clears the queue. A
   short "What's sent" view lists the events in plain words. Vitest for the
   toggle.
6. [auto] The PostHog project API key comes from build config (env var at
   build time, e.g. DICTATION_POSTHOG_KEY). Without it, the adapter is a
   no-op (dev builds, CI and forks send nothing). Never commit a real key.
7. [auto] Docs: replace "No analytics or telemetry" in docs/ENGINEERING.md and
   "analytics stay off" in AGENTS.md with the rules above (what may and may
   not be sent, on by default, off switch); add docs/privacy.md listing every
   event and property. AGENTS.md is not a guard file; don't touch guard
   files.
8. [auto] Gate passes; cargo deny passes for any new crate.

## Out of scope

Sentry/crash reporting (A2), onboarding redesign (the analytics disclosure
screen comes with it), dashboards.
