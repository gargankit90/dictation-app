# M5.4: DMG, tester README and updater

## Goal

Something we can hand to alpha testers: a DMG they can install by
following one README, and an app that updates itself to newer alpha
builds without losing its permissions.

  its password live only in the owner's login Keychain, as generic
  passwords with services `dictation-app-updater-key` and
  `dictation-app-updater-password` (account = the user). Public key, for

- **Releases:** the public repo `gargankit90/dictation-app-releases`

  `releases/latest/download/latest.json`.

## Scope

- DMG signed with `dictation-app Dev` (not notarised). The existing DMG
  workflow stays as the CI artifact.
- Updater plugin (`tauri-plugin-updater`) with the public key above and
  the endpoint above: check on launch and from a tray "Check for
  updates…" item; download, install and relaunch only after the user
  agrees. Keep the existing single-instance and relaunch paths.
- A release script (e.g. `scripts/release.sh <version>`) that the Lead or
  owner runs on this Mac: builds the signed release, reads the two
  Keychain items into `TAURI_SIGNING_PRIVATE_KEY` /
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` for the build only (never echoed,
  logged or written to disk), writes `latest.json`, and with `--publish`
  uploads to the releases repo with `gh release create`. Without
  `--publish` it only builds into a local folder (dry run). No CI
  publishing and no new tokens.
- Tester README (in the releases repo's README text, kept in this repo as
  `docs/TESTERS.md` so it's reviewed): install from the DMG, clearing
  quarantine, granting Accessibility and Microphone, getting a Groq key,
  how updates arrive, sending logs (without keys or transcripts).

## Out of scope

- Developer ID signing and notarisation (needs the Apple account).
- Publishing the first real release: the owner approves that separately.

## Acceptance criteria

1. `[auto]` CI builds the DMG as an artifact (already true; keep it).
2. `[auto]` The release script's dry run produces a signed updater bundle,
   its `.sig` and a `latest.json` whose signature verifies against the
   public key; shell tests prove it never prints the key or password and
   refuses `--publish` without a clean tree and a version tag.
3. `[auto]` In a freshly restored VM, following only `docs/TESTERS.md`:
   quarantine, permissions, first dictation (local provider seam).
4. `[auto]` In the VM, the updater finds a newer local test release
   (served from a local fixture endpoint, not the public repo), installs
   it after the user agrees, and Accessibility and Microphone permission
   still hold after the update.
5. `[auto]` A tray "Check for updates…" item; "you're up to date" and
   "update failed" are shown plainly; a bad signature is refused.

Every milestone also needs: the gate green, coverage at or above
thresholds, `Tester: PASS` and `Reviewer: APPROVED` on the PR.
