# B1: Engine recovers after a keychain timeout at launch

Closes #204.

At launch the keychain may not answer within KEY_READ_TIMEOUT (15 s), for example while macOS shows its "allow access" prompt for a newly signed build. The startup rebuild then makes the engine Unavailable with a keychain error, and nothing rebuilds it later: the onboarding key test can read the stored key fine (`API key works source="stored"`), yet every dictation fails with the stale keychain error until the app restarts.

Acceptance criteria:
1. [auto] When the engine is Unavailable because the key READ failed or timed out (not because no key is saved, not a settings error, not a pinned/test engine), the next dictation retries: it rebuilds the engine from the config (bounded by the same key timeout, off the event loop, sharing KeyReads so no extra stuck threads) and transcribes with the new engine if that succeeds. If the retry fails too, the user sees the same keychain error as today. A test with a fake SecretStore that times out (or errors) first and answers on a later read proves the second dictation succeeds without a restart.
2. [auto] A successful read of the stored key anywhere else (the onboarding/Settings key test with source "stored", and onboarding::key_saved when it returns true) also rebuilds the engine if it is currently Unavailable for a keychain reason, so the "Try it" step works right after the user allows access. Test with the same fake.
3. [auto] No rebuild loop and no extra keychain reads when the engine is fine or when no key is saved: a test counts reads on the fake for (a) a working engine, (b) no key saved, (c) a keychain that keeps failing (at most one read per dictation, still bounded by KeyReads).
4. [auto] The onboarding key step shows success when "Test and continue" passes with the saved key (owner thought it hadn't tested anything): a short visible "Key works" confirmation before or while advancing, with a vitest test. Keep copy short and plain.
5. [auto] No key or transcript in any log at any level; existing tests still pass; the gate (scripts/gate.sh) passes.
6. [manual] On the owner's Mac or the VM: launch with the keychain prompt pending (or a fake delay build), allow access, then dictate in onboarding's Try step without restarting: text is pasted. The Tester covers this in the VM if a test hook can simulate the slow keychain; otherwise note it for the Lead.

Out of scope: changing KEY_READ_TIMEOUT, the updater, other onboarding redesign (a separate research task is collecting other apps' onboarding flows).
