# Q3: Connect OpenRouter in one click, and make credits easy

Owner decision, 2026-11-20: one key, the user's OpenRouter key; "make it as easy as we can for end users
to create an OpenRouter key and also to top up their account with money". Builds on Q2 (OpenRouter
provider, Keychain account `openrouter-api-key`, typed 401/402 errors). Start from Q2's branch or from
main after Q2 merges.

## Scope

1. **Connect OpenRouter (OAuth PKCE)**, per https://openrouter.ai/docs/use-cases/oauth-pkce:
   - Generate a `code_verifier` (random, kept in memory only) and S256 `code_challenge`.
   - Start a one-shot loopback HTTP listener on `127.0.0.1` with a random free port; open the browser at
     `https://openrouter.ai/auth?callback_url=http://localhost:<port>/callback&code_challenge=<c>&code_challenge_method=S256`
     (verify the exact host OpenRouter accepts: `localhost` vs `127.0.0.1`).
   - On the callback, check a `state`-equivalent (reject a code that doesn't belong to this attempt),
     POST `https://openrouter.ai/api/v1/auth/keys` with `{code, code_verifier, code_challenge_method:"S256"}`,
     store the returned key in the Keychain, never log it, show a "Connected — you can close this tab"
     page, and close the listener. Time out after 5 minutes; cancelling works.
   - Pass `key_label=Vocet on <Mac name redacted to "this Mac">` only if the API supports it; never send
     hostnames or usernames.
   - Fallback when no browser callback arrives: "Paste a key instead" (Q2's paste field).
2. **Onboarding** (cloud path): one primary button "Connect OpenRouter"; a short explainer: "Vocet uses
   your OpenRouter account. You pay OpenRouter directly — about $0.70 per 1,000 dictations. New accounts
   need a few dollars of credit." Secondary: "I'll use Vocet on this Mac only" (Private mode, Q4).
3. **Credits**: buttons that open `https://openrouter.ai/settings/credits` (verify the current URL).
   - On a 402 from any request: the overlay/menu error reads "Your OpenRouter credits ran out. Add
     credits" with that link as the fix action (U1/U5 error → fix mapping).
   - No balance display and no key-limit special case in this milestone (minimum complexity).
4. Settings → Cloud: Connected status (masked key, never the full key), "Disconnect" (deletes the Keychain
   item), "Add credits", and the models in use (from Q2's catalog).
5. **Delete the old own-key UI** in the same change: `src/settings/ownKey.tsx`, `providers.ts`, `keyTest.ts`,
   the Groq/OpenAI language lists and their tests (whatever Q2 left), so there is one key flow only.
6. Privacy copy: the OAuth flow sends no Vocet user data; the key stays in the Keychain.

## Acceptance criteria

1. [auto] PKCE unit tests (verifier length/charset, S256 challenge vectors); the listener accepts one
   valid callback, rejects others, times out, binds only to loopback.
2. [auto] Exchange tests against a local HTTP fake: success stores the key (fake Keychain); failures map
   to clear errors; the key never appears in logs.
3. [auto] 402 → "Add credits" fix action in the overlay/menu mapping tests.
4. [auto] Gate passes; e2e onboarding screenshots updated (fake OpenRouter).
5. [manual] Lead in the VM: Connect OpenRouter with a real account; dictation works; Disconnect removes the key.
