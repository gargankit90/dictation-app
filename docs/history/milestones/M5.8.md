# M5.8: password fields and quitting mid-request

## Goal

Two things a user should be able to trust: the app never reads what they
type into a password field, and Quit while a transcription is in flight
ends cleanly, with no paste afterwards and no extra provider call. Plus a
property test that actually exercises accidental taps. From the open
issues on 2026-11-02 (#135, #115, #31).

## Scope

- **#135 password fields.** `crates/platform/src/cursor/macos.rs` skips
  `AXSecureTextField` and Secure Input, but if reading `AXSubrole` itself
  fails, the field is read. Fail closed: when the subrole can't be read,
  don't read the field (treat it as no context: no added space, nothing
  read). Prove the skip for real with a VM scenario that focuses a
  password field (a small AppKit fixture or an existing secure prompt in
  the VM) and asserts no space is added and nothing is read; if a test
  seam makes the fail-closed branch testable without the VM, add a unit
  test too.
- **#115 Quit during a real request.** A pipeline/app test using the
  existing local HTTP rig: wait until the local server receives the
  request, call the real `Pipeline::shutdown` (or the shell's Quit path),
  see the connection close, then release a delayed response and assert no
  insert, no retry, shutdown within a bound, and a fresh pipeline works.
  Add the variant where shutdown happens during retry backoff. A VM
  scenario `e2e_quit_during_transcription_then_relaunch` using T4a's local
  provider seam (`--debug-provider-url`): click the tray Quit after the
  fixture signals the request arrived; the process exits promptly, nothing
  is pasted, and a relaunch dictates normally.
- **#31 taps in the property test.** The unit proptest in
  `crates/core` draws gaps from 0..400 000 ms, so taps under 200 ms almost
  never appear. Use a mixed gap strategy (human-scale and long gaps) so the
  tap branch is exercised; show that a mutant of the tap branch fails it.

## Out of scope

- CI artifact upload (#128) and the VM runner for CI (#104).

## Acceptance criteria

1. `[auto]` When `AXSubrole` can't be read, the cursor reader returns no
   context (fail closed); a test proves it, or the PR explains why only
   the VM scenario can.
2. `[auto]` A VM scenario with a focused password field: dictation adds no
   space and the field isn't read (no context in the debug log).
3. `[auto]` Pipeline/app test: shutdown during an in-flight real HTTP
   request closes the connection, never inserts or retries, finishes
   within a bound, and a fresh pipeline works; plus the backoff variant.
4. `[auto]` `e2e_quit_during_transcription_then_relaunch` passes in the VM.
5. `[auto]` The core proptest generates sub-200 ms taps; a tap-branch
   mutant fails it.

Every milestone also needs: the gate green, coverage at or above
thresholds, `Tester: PASS` and `Reviewer: APPROVED` on the PR.
