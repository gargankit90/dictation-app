# M5.5b: feels solid: the hotkey comes back by itself, Esc never leaves it stuck

## Goal

The hotkey must keep working without the user restarting the app. Today, if
the hotkey listener dies (Accessibility revoked, the event tap disabled),
the app shows an error asking for a restart; and if macOS drops a modifier
release, pressing Esc can leave the hotkey stuck so the next press is
ignored. Part 2 of M5.5 "Feels solid" (part 1, M5.5a, merged as `m5.5a`).

## Scope

- **#88 restart the hotkey listener automatically.** When the listener dies,
  show a "hotkey unavailable" tray state and keep retrying with backoff
  (`core::retry` or the same policy) until it starts again, e.g. once
  Accessibility is granted again; then clear the error and the tray state.
  The retry must stop on Quit, must not spin the CPU, and must not create a
  second listener if one is already running. A Settings hotkey change while
  retrying uses the new hotkey.
- **#88 vendored crate tests.** Run the tests of `third_party/handy-keys`
  and `third_party/coreaudio-rs` (not workspace members) in
  `scripts/gate.sh` and so in CI. Keep the gate under ~10 minutes.
- **#47 Esc after a missed modifier release.** In
  `crates/platform/src/hotkey/matcher.rs`, Esc (down, repeat and up) must
  also reconcile `active` with the modifiers the event reports, so a stuck
  active state is cleared and the next hotkey press starts a recording.
  Cover the second case in the issue too.

## Out of scope

- #50 (Accessibility re-grant not picked up until relaunch) goes with M5.2
  onboarding, unless the #88 restart fixes it as a side effect; if so, say
  so in the PR and add a test.

## Acceptance criteria

1. `[auto]` Pipeline/app tests with a fake hotkey factory: a dead listener
   gives the "hotkey unavailable" state; retries back off; when the factory
   succeeds the listener is back, the error and tray state clear, and the
   next press dictates. Quit stops the retries. No second listener starts.
2. `[auto]` A Settings hotkey change during retries is the hotkey that comes
   back.
3. `[auto]` The matcher tests for both #47 cases pass and fail on the old
   code.
4. `[auto]` `scripts/gate.sh` runs the handy-keys and coreaudio-rs tests;
   a failing test there fails the gate.
5. `[auto]` A VM scenario `e2e_hotkey_listener_recovers` on `dictation-vm`:
   make the listener die (for example revoke Accessibility for the app with
   `tccutil` in the VM, or a test-build hook that kills the tap), see the
   unavailable state, restore, and a hold dictates again without a relaunch.
   If revoking in the VM isn't possible without touching the golden image,
   use the test-build hook and say why in the PR.
6. `[manual]` On the owner's Mac: turn Accessibility off for the app, then
   on again; the hotkey works again within a few seconds without a relaunch.

Every milestone also needs: the gate green, coverage at or above thresholds,
`Tester: PASS` and `Reviewer: APPROVED` on the PR.
