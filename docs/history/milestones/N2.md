# N2: switch releases to Developer ID and notarization (#206)

On 2026-11-09 the owner created the certificate "Developer ID Application:
Ankit Garg (XF2G42MVHN)", stored the notarytool profile `vocet-notary`, and ran
the N1 test signing run on `631c37d`. Both runs passed: the app and the DMG were
accepted by Apple, stapled and passed Gatekeeper ("Notarized Developer ID"); the
updater bundle and the DMG hold the same notarized app, and the minisign
signature verifies. The Lead checked the DMG separately with `stapler validate`
and `spctl`. That build says "Test signing run." and is never published. There
has never been a public release, so no tester is moving from a dev-signed build.

Agents never read the updater key, the Keychain items or an Apple credential,
never run `scripts/release.sh`, and never sign with the owner's certificate.

   Application: Ankit Garg (XF2G42MVHN)` and keeps
   `RELEASE_NOTARY_PROFILE=vocet-notary`. `scripts/test-release.sh` still
   passes: a configured identity that can't sign fails and doesn't fall back,

   successful test signing run is recorded. The "Moving testers to Developer ID"

   `tests/e2e/scenarios/e2e_notarized_dmg_first_launch.sh`. It takes a DMG path

   the VM, sets `com.apple.quarantine` on it the way a browser download would,
   mounts it, copies `Vocet.app` to `/Applications` and opens it. It passes with
   no `xattr` step, and `spctl --assess` inside the VM reports Notarized
   Developer ID. It is optional (skipped when no notarized DMG is given) and
   doesn't run in CI. If Gatekeeper shows its prompt, that is expected: Open is
   clicked and what the person sees is recorded, with a screenshot.
