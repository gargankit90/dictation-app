# T1: regression oracles and pipeline fixes

## Goal

Tests that fail when the bugs users would notice come back: a recording that
keeps running, Test key sending a broken clip or hanging, the app hammering the
provider, and patched mic/hotkey crates regressing unnoticed. Fix the product
bugs those tests expose. From the test audit, #103 (T1 in its milestone split),
plus the remaining M4.5 cleanup issues.

## Scope

- **P1-02 / #88:** run the vendored crates' patch tests in CI's macOS job and
  in `scripts/gate.sh` on macOS (`third_party/handy-keys --lib dictation_patch`,
  `third_party/coreaudio-rs --lib patch_tests`, dedicated `CARGO_TARGET_DIR`s,
  dependency versions reconciled with the app's lockfile). #88's "restart the
  hotkey listener automatically" part: do it if small, otherwise leave #88 open
  for it.
- **P1-04 / #91 / #84:** after a queue overflow or a dropped hotkey event, the
  pipeline ends Idle with no open recording and no transcription, without any
  corrective key press; the cancel for a dropped event can't run before keys
  still queued (#91); the UI event queue is bounded with a documented
  coalescing/error policy (#84); an abandoned runner still closes its audio
  worker; every stale job-result variant (NotTranscribed, Inserted, both
  AudioFailed branches) is ignored for an old job ID.
- **P1-05 / #86:** Test key uploads exactly 250 ms of 16 kHz mono 16-bit
  silence (4,000 samples), never sends a language even if one is configured,
  uses its own deadline and never retries; key lookups in `has_api_key` and the
  stored-key path of `test_api_key` are bounded (reuse M4.4's KeyReads, no new
  thread per retry) and the UI can retry afterwards; a 3xx reply gets a clear
  message (#86).
- **P2-02 (HTTP lifecycle only):** shutdown aborts an in-flight request without
  a retry; abort during backoff sends no next request; partial and truncated
  bodies time out or fail with a safe error; the real `TokioWait` honours its
  delay (paused time).
- **P2-03 (deterministic oracles):** a v2 settings file isn't migrated as v1;
  debug-recording names stay unique under a fixed timestamp with occupied
  suffixes; bound the request-arrival loops in `transcribe/tests/engine.rs` so
  a broken mutant fails instead of hanging.
- **P2-04 (coverage only):** `scripts/coverage.sh` fails closed for a crate with
  no tests; remove `--no-tests=pass` (#33, #62).
- **Hotkey edge cases #47, #89:** Esc after a missed modifier release clears the
  stuck state; a synthetic event with different flags can't cancel a recording.
- **Small CLI/shell items #73, #70:** `--debug-audio-file` without a path is an
  error, not a swallowed next flag; no duplicate unknown-engine warning on a
  second launch.

## Out of scope

- Single-instance races (P1-01), the hotkey-setting application (P1-03), VM
  in CI (P1-06), native UI tests: T2.
- Log redaction (#65, #60, #61, #64, #41): M5.3.

## Acceptance criteria

1. `[auto]` CI's macOS job runs the vendored hotkey and CoreAudio patch tests;
   reintroducing the #77 capacity bug or the #80 decode bug in `third_party`
   makes CI fail.
2. `[auto]` An overflow/dropped-event test with queued Pressed/Released/Cancel
   permutations ends Idle with no recording and no transcription, with no
   corrective Esc and no sleep used as proof (use fences/barriers).
3. `[auto]` The UI event queue is bounded; a stalled consumer keeps bounded
   memory, gets the documented coalesced state/error, and recovers.
4. `[auto]` A table-driven test shows every stale job-result variant is ignored
   for an old ID and handled for the current one; removing any one current-job
   guard makes it fail.
5. `[auto]` Test key: the decoded upload is exactly 4,000 zero samples at
   16 kHz mono 16-bit with no language; a stalled server gives one request and
   a Timeout at the check's own budget; a never-answering keychain lookup is
   bounded and the UI offers retry.
6. `[auto]` HTTP lifecycle tests (shutdown/backoff abort, partial and truncated
   body, `TokioWait`) pass and fail when the corresponding code is removed.
7. `[auto]` `cargo mutants` on the touched files: the survivors listed in #103
   for Test key, stale results, AudioWorker drop, TokioWait, body
   classification, settings migration and debug save collision are now caught
   (report the before/after list in the PR).
8. `[auto]` `scripts/coverage.sh` without `--no-tests=pass` fails for a crate
   with no tests (fixture) and passes on the repo.
9. `[auto]` Tests for #47, #89, #73, #70 and #86 as described in each issue.
10. `[manual]` none beyond the VM suite: `tests/e2e/run.sh` still passes.

Every milestone also needs: the gate green, coverage at or above thresholds,
`Tester: PASS` and `Reviewer: APPROVED` on the PR.
