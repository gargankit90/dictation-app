# E2F2: Terminal window pile-up in full VM e2e runs

Closes #276. Root cause: `close_terminal` kills Terminal with SIGTERM, macOS
restores its windows on the next launch, and the `rm` of the savedState path
does nothing on macOS 15.6.1, so idle login shells pile up (470 at the end of a
full run) until jobs starve at the per-user process limit (1333).

## Acceptance criteria

1. [auto] After every VM reset, and at the start of any run that skips the reset, the harness sets `defaults write com.apple.Terminal ApplePersistenceIgnoreState -bool true` in the clone. `dictation-vm-golden` is never changed. No step launches Terminal before this.
2. [auto] The dead `rm` of the savedState path is removed from `close_terminal`.
3. [auto] Between scenarios the run logs the lume user's process count and `login` count, and stops with a clear message if either passes a threshold well below 1333. `tests/e2e/test-runner.sh` covers it.
4. [auto] `VM_TERMINAL_TIMEOUT` is unchanged.
5. [auto] `e2e_quit_right_after_paste`: the quitter reports ready before the dictation starts (no fixed 2 s sleep), and the scenario checks the wait status. If it still fails, find out whether the test or the app is wrong (#270) and say which.
6. [auto] One complete full-suite run on this branch has no Terminal job timeouts and a low `login` count throughout; the summary line and peak counts go in the PR.
7. The PR states from that run whether `accessibility_revoked` (#271) and `quit_right_after_paste` (#270) pass; the Lead closes the issues.
