# U5: The menu-bar menu as Vocet's home

Build spec from the Design Lead, 2026-11-03. High value tonight, with U4. Design: ~/Documents/dictation-design/design-system/index.html, the "Menu-bar menu" section. Native NSMenu via Tauri's tray menu; no custom webview menu.

## Why

Today:
- The menu lists maintenance tools: Settings, Set up dictation, Troubleshoot, Check for updates, Reveal log, Quit.
- It never says whether dictation is ready, which key to hold or which engine is used.
- On an error, the menu-bar item grows to "⚠ Dictation failed", which takes a lot of room on crowded or notched menu bars.

Both reviews (Claude 4 and 5, Codex 11 and 12).

## Design: menu layout, top to bottom

1. **Status** (disabled item, always first):
   - Ready: "✓ Ready · Hold Right ⌥" with a second line or suffix "On this Mac (Parakeet English)" / "Groq" / "OpenAI". Use the real key and engine names.
   - Not ready: "! <the one-sentence problem from U1>", e.g. "! Your Groq key was rejected".
   - While a model downloads: "↓ Downloading Parakeet English, 42%".
2. **Fix row**, only when not ready. One enabled item whose label names the action, mapped from the error code:

| Problem | Fix item |
|---|---|
| key rejected or missing | "Open Speech settings…" (Settings, focused on the key/engine) |
| microphone denied | "Open Microphone settings…" (System Settings → Privacy & Security → Microphone) |
| Accessibility missing | "Open Accessibility settings…" |
| a grant needs a restart | "Relaunch Vocet" (replaces today's separate Relaunch item) |
| model not downloaded or failed | "Download the model…" (Settings → Speech) |
| hotkey unavailable | "Choose another key…" (Settings → shortcut) |
| anything else | "Troubleshoot…" |

3. Separator.
4. **"Copy last dictation"**: enabled only when a dictation happened in this session; copies its text to the clipboard. The text is **not shown** in the menu (privacy; owner may revisit). It's kept in memory only and cleared on quit, until U7 adds history.
   - **"History…"**: added by U7, not in this milestone.
5. Separator.
6. "Settings…" (⌘,) · "Troubleshoot…" · "Report a problem…" (opens Troubleshoot's report preview).
   - "Resume setup…" appears only while onboarding is incomplete. Rename "Set up dictation…" and hide it once setup is done; setup stays reachable from Settings → Help.
7. Separator.
8. "Check for updates…" · "Quit Vocet" (⌘Q).

"Reveal log" leaves the menu and moves into Troubleshoot (a "Show log file" button).

### Menu-bar icon

- A monochrome template image: the three-bar mark from DS1.
- Problem state: the same mark with a small dot (a template image variant, so it adapts to light, dark and tinted menu bars). **No text title next to the icon** in any state.
- Recording: the bars may fill or invert. Optional, only if it's a template variant; the pill already shows recording.
- Tooltip: "Vocet: Ready" / "Vocet: <problem sentence>".

## Acceptance criteria

1. [auto] The tray menu is built in the order above. A test enumerates item IDs and labels for each state: ready (local), ready (Groq), downloading, each problem row in the table, and setup incomplete.
2. [auto] The status item is disabled and reflects the live state: the key name formatted like HotkeyRecorder's display ("Right ⌥"), and the engine's display name. It updates within 1 s of a state change (key changed, engine switched, error raised or cleared).
3. [auto] Each problem maps to exactly one fix item, which performs the action in the table. A test covers the mapping for every user-facing error code (the same list as U1 criterion 5). Unknown codes get "Troubleshoot…".
4. [auto] The tray **title is never set** (no text beside the icon). The problem state uses the dot-variant template icon. Template images (black + alpha) are provided by the Design Lead at 1× and 2× in ~/Documents/dictation-design/design-system/tray/ (trayTemplate, tray-attentionTemplate, tray-recordingTemplate, plus an SVG); copy them to `src-tauri/icons/tray/` and set them as template images.
5. [auto] "Copy last dictation" is disabled until a dictation succeeds in this session, then copies exactly that text. Its text is never written to disk, logged at info level, shown in the menu, or included in reports or analytics. It's cleared on quit.
6. [auto] "Reveal log" is removed from the menu; Troubleshoot gets "Show log file". "Relaunch Vocet" appears only as the fix row. "Resume setup…" is shown only while onboarding is incomplete.
7. [auto] Existing tray-related e2e scenarios (e2e_tray_error_clears_on_next_recording and others) are updated: they assert the status/fix items and the icon state instead of the tray title.
8. [manual] In the VM, in light and dark menu bars:
   - The idle icon, the problem icon (with dot) and the open menu in the ready and bad-key states.
   - A crowded menu bar doesn't push the icon off.

   Screenshots go on the PR.
