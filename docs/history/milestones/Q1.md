# Q1: The eval harness on main, with a regression check and end-to-end latency

Owner decision, 2026-11-20: "All the eval work we did we should figure out a way to get it in our code."
Today the eval tooling is spread across ten draft PRs (#322–#332, branches `eval/*`, `exp/*`) that will
never merge, and one worktree was lost with uncommitted work. Bring one clean harness to `main`.

## Scope

1. One `eval/` package on `main` (Python, run with `uv`), consolidating the best version of each piece:
   - Dataset fetch (Voice Arena public set; **never commit audio**: CC BY-NC) and the tune/check split by
     sha256(speaker_id) (`eval/voicearena/` on branch `eval/voicearena`, PR #323).
   - Engine runners: OpenRouter speech (`eval/hosted-asr/transcribe_openrouter.py`, PR #330), local
     (`/tmp`-free version of the ASR screen runner, PR #331), and "the app itself" via the e2e harness
     (PR #323's VM runner) — keep the VM runner if it is small; otherwise document it.
   - Offline cleanup runner over saved transcripts (`eval/cleanup-offline/offline_cleanup.py` + `guard.py`,
     PR #327), reading prompts from the app's own prompt file (Q2) so eval and app can't drift.
   - Judges with one interface and shared cache: Claude (`score_claude_cli.py`), Codex
     (`score_codex_cli.py`, PR #325), Gemini via Antigravity (`score_gemini_cli.py`, PR #332, with the
     `GEMINI_JUDGE_MODEL` option: default a Flash model, not Argon).
   - One summary/report script: ZER, AMEND, check half, paired wins/losses, cost per 1,000, latency.
   - Keys only from environment variables; never logged; spend caps; 429 retry — as the eval scripts do.
2. **Regression subset**: a fixed list of ~40 clips (both halves, all domains) and `eval/regress.sh` that
   runs the app's current cleanup prompt on saved transcripts and reports ZER vs the stored baseline.
   Not part of the gate (it costs API calls); documented in `docs/ENGINEERING.md` as required before
   merging any prompt or model-default change.
3. **End-to-end latency**: the e2e harness records key-up → paste time per dictation (VM), reported as
   p50/p95 in the e2e results; no network needed with the mock engine (records the pipeline overhead).
4. Results: keep the final numbers (CSV + REPORT.md) from PRs #323, #327, #330, #331, #332 under
   `eval/results/` (text only, no audio, no keys), with a top-level `eval/README.md` that says which
   result supports which product default.
5. Python tests (existing ones from the eval branches) run in the gate only if they need no network and
   take < 30 s; otherwise a documented `uv run pytest eval`.

Out of scope: new evaluations, new judges.

## Acceptance criteria

1. [auto] `git grep` finds no audio files or API keys under `eval/`; `.gitignore` covers clip folders.
2. [auto] `uv run pytest eval` passes offline; the gate stays green and not slower by more than 30 s.
3. [auto] `eval/regress.sh --dry-run` prints the plan and cost estimate without network.
4. [auto] e2e results include key-up-to-paste p50/p95.
5. [manual] Lead runs one real `eval/regress.sh` with the owner's OpenRouter key and checks the report.

`origin/eval/*`; do not edit other workers' worktrees.
