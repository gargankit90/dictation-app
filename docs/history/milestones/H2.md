# H2: say so when a dictation had no sound

Owner-approved fix before 0.1.0. While the key is held with no sound the pill
shows "No sound" after 2.5 s. On release a silent clip returned to Idle with
nothing shown, so someone with a dead or wrong microphone who didn't watch
the pill, or who held for under 2.5 s, got no explanation. Dropping silent
clips stays correct: it stops key clicks and invented words (#69, #72, #172).

Design: `specs/U13.md` (the pill's states and the 6 s error time).

## Acceptance criteria

1. [auto] On release, if the clip's verdict is `Verdict::Silent` and it
   lasted at least 1 s, the pill shows the problem and the mic's name if
   known, using the pill's existing error presentation and time (6 s). It
   reuses the existing "No sound" wording and device name from the recording
   state unless that doesn't read right after release; if so, the PR proposes
   wording for the Design Lead.
2. [auto] No message for a quick tap or key click: `Verdict::TooShort`,
   `Verdict::NoSustainedSound`, `Verdict::Empty`, or a silent clip under 1 s.
   These still return to Idle silently.
3. [auto] Nothing is sent to a provider and nothing is pasted, as today.
   Silent clips stay out of History.
4. [auto] It's a one-off: the menu bar doesn't go into its attention state,
   the next dictation clears the pill, and pressing the key while it shows
   starts recording normally. Esc or a cancelled recording shows no message.
5. [auto] Analytics: only the existing closed `Event` enum. No new event, no
   device name. If an existing event fits, the PR says which; if none does,
   none is sent and the PR notes that.
6. [auto] Unit tests for the state transitions and the 1 s boundary, in
   `crates/core` with no I/O where possible. VM: `e2e_silence` or
   `e2e_pill_states` checks for the message after a silent hold, and that a
   short tap shows none. `e2e_silence` keeps its "the pipeline never inserts"
   check.
7. [manual] Light and dark window-only screenshots of the pill after a silent
   hold, with a short and a long mic name, on the PR for the Design Lead.
