# T7: Unicode paste scenario seeds its document correctly

Closes #185.

## Goal

`e2e_unicode_multiline_selection_paste` fails on every run (e576964, ffc87c0):
TextEdit holds the scenario's surrounding text still base64-encoded around a
correct transcript. The app's paste is right; the document setup is not.
Test-only; no product code changes unless the app is proven at fault (then
stop and ask the Lead).

## Acceptance criteria

1. [auto] Root cause found and explained in the PR: how this scenario seeds
   TextEdit versus the scenarios that pass, and when it last passed.
2. [auto] The seeding is fixed: TextEdit holds exactly the intended Unicode
   text (emoji, combining marks, RTL, tabs, blank lines) before dictation.
3. [auto] The scenario checks the seeded document itself first and fails with
   a clear "setup: document not as expected" message (not a paste failure) if
   seeding goes wrong; a fixture test proves that message appears when
   seeding is broken.
4. [auto] The scenario passes 3 times in a row on `dictation-vm`, and the other
   scenarios that seed documents still pass (run once).
5. [auto] No existing check is weakened; the three paste assertions stay exact.

## Allowed edits

`tests/e2e/` (scenarios, helpers, fixtures, README), `docs/milestones/T7.md`.
