# U1: Vocet name and honest, actionable feedback

Build spec from the Design Lead, 2026-11-03. Part of the UX backlog (~/Documents/dictation-design/plan-ux-backlog.md). Needs no new visual design: copy and state fixes in today's UI. Related: #209 (error diagnosis), #210 (onboarding).

## Why

Both UX reviews (claude-app-ux-opinion.md and codex-app-ux-opinion.md in ~/Documents/dictation-design/) found these:
- The app calls itself "dictation-app".
- Errors show raw codes and no next step.
- "Try it" says "It works" when the user just types.
- Troubleshoot offers a key test that does nothing in local mode.

## Owner decisions

- The name people see is **Vocet**.
- **Keep the internal identifiers**, so testers keep their permissions, settings and saved key: the bundle identifier `com.dictationapp.desktop`, the app-data folder, the Keychain service/account names, and the log file prefix.

## Acceptance criteria

1. [auto] Every user-visible string in the app says **Vocet**, not "dictation-app":
   - the tray tooltip and menu ("Quit Vocet", "Relaunch Vocet")
   - window titles ("Vocet Settings", "Set up Vocet", "Vocet Troubleshoot")
   - onboarding, Settings and Troubleshoot copy
   - relaunch and error messages in src-tauri
   - the microphone purpose string in Info.plist
   - the macOS app name (`productName`) and the name shown in Login Items and permission prompts

   A test (or the gate) fails if "dictation-app" appears in user-visible strings in `src/` or `src-tauri/src/` (excluding tests and internal identifiers).
2. [auto] The bundle identifier, app-data folder, Keychain service/account and log file prefix are unchanged. Existing saved settings and the saved key still load after the update; a test covers this.
3. [auto] If the `.app` file name changes (`Vocet.app`), every script and e2e scenario that references the old path is updated, and the DMG/release scripts still pass their tests.
4. [auto] The recording-pill error shows **one plain sentence and no error code**. Codes such as `key_rejected` and `mic_denied` are no longer rendered in the overlay. They stay in Troubleshoot ("Details") and in the Report a problem preview.
5. [auto] Each error sentence names the fix in user terms. Examples: "Your Groq key was rejected. Open Settings → Speech to fix it." / "Vocet can't use the microphone. Allow it in System Settings → Privacy & Security → Microphone." / "No API key saved. Add one in Settings, or use the model on this Mac." The tray tooltip and menu-bar title use the same sentence, not the code. A test checks that every user-facing error code has a message with a fix.
6. [auto] Onboarding **Try it** shows success **only after the app reports a completed dictation** (recorded → transcribed → pasted) while the step is open. Typing in the practice box, or any non-empty text, never shows success.
   - The success copy lists the stages that were observed.
   - "Skip for now" is a clearly labelled secondary action. When used, Finish says the test was skipped, not that it worked.
7. [auto] Try it's failure hint no longer says "the menu bar icon says what". It shows the latest dictation error's sentence (from criterion 5) inline, next to the practice box.
8. [auto] Troubleshoot hides the "Test connection" button when the local model is the engine. In its place it shows a local readiness line (model downloaded / loading / ready / error). The connection test still shows for Groq/OpenAI.
9. [manual] In the VM, these show Vocet with no raw codes:
   - first launch: the onboarding window and the permission prompts
   - a bad-key dictation: the overlay sentence and the menu-bar text
   - the Quit menu item

   Screenshots are attached to the PR. Microphone and Accessibility grants from the previous build still work after updating (same identifier).
