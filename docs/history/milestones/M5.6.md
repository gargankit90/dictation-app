# M5.6: hardening: no stuck Command key, honest hotkey state, useful crash logs

## Goal

Fix the open bugs a user could notice after M5.5b and M5.2: a Command key
that may stay "held" for other apps after we paste, a hotkey outage the tray
or overlay reports wrongly, a permission check with the wrong C type, and
crash logs that don't say what went wrong. From a triage of the open issues
on 2026-11-01.

## Scope

- **#140 synthetic ⌘V and the session's modifier state.** First find out:
  in the VM, read `CGEventSourceFlagsState` for the combined and HID
  sessions before and after one dictation's paste. If Command stays set,
  fix the paste (e.g. post explicit Command down/up with a private event
  source, or clear the flags on the key-up) so no app sees Command held
  afterwards. If it doesn't, say so in the PR with the evidence, add the
  check as a VM scenario step so it can't regress, and close #140.
- **#154 newest hotkey outage survives a full UI error queue.** Keep or
  coalesce the latest hotkey availability transition (`HotkeyFailed` /
  `HotkeyRestored`) even when the error queue is full, so the tray always ends
  on the real listener state.
- **#155 overlay clears a hotkey error when listening resumes.** On
  `HotkeyRestored`, hide a showing hotkey-failure overlay; leave other
  dictation errors alone.
- **#46 `AXIsProcessTrusted*` return `Boolean`.** Declare them as returning
  `u8` and compare `!= 0`, like `IsSecureEventInputEnabled`.
- **#144 useful panic logs, installed early.** Log a `&'static str` panic
  message (it can't contain a key or transcript); keep formatted `String`
  payloads hidden at info level (debug mode may show them). Install the hook
  before anything that can panic or fail, including before logging init.

## Out of scope

- Guard changes (#21, #22, #23, #28: owner only). #50 (owner check).

## Acceptance criteria

1. `[auto]` #140: the VM evidence (before/after flags) is in the PR, and
   either a fix plus a VM step proving Command is clear after a paste, or the
   step alone proving it already is.
2. `[auto]` #154 and #155: the issues' deterministic reproductions are now
   tests that pass, and fail on the old code.
3. `[auto]` #46: the declarations use `u8`; existing permission tests pass.
4. `[auto]` #144: tests prove a literal panic message reaches the log, a
   formatted one with a unique sentinel does not (at info level), and the
   hook is installed before logging init.
5. `[auto]` The 39 key-handling checks and the existing VM paste scenarios
   still pass.

Every milestone also needs: the gate green, coverage at or above thresholds,
`Tester: PASS` and `Reviewer: APPROVED` on the PR.
