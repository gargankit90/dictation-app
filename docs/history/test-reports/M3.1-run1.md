## Failures

### 1. Major: `RetryPolicy::delay_after` panics on a huge cap or NaN jitter

`crates/core/src/retry.rs`, `delay_after`: `backoff.mul_f64(1.0 - cut)`.
`Duration::mul_f64` goes through f64 seconds and panics
(`cannot convert float seconds to Duration: value is either too big or NaN`)
when the result rounds past `u64::MAX` seconds or is NaN. `f64::clamp` passes
NaN through, so a NaN `jitter` or a `RandomSource` returning NaN also panics.

Reproduce:

```sh
cargo nextest run -p dictation-core --test retry_edges --run-ignored all
```

```rust
RetryPolicy { multiplier: u32::MAX, max_delay: Duration::MAX, jitter: 0.0, ..p }
    .delay_after(40, &mut rng) // panics; Retry::failed panics the same way
RetryPolicy { jitter: f64::NAN, ..p }.delay_after(1, &mut rng) // panics
```

Expected: saturate (the PR notes say "Overflow saturates at the cap", and
the unit test `backoff_saturates_instead_of_overflowing` uses exactly this
`Duration::MAX` cap, but only calls `backoff`). Actual: panic, which in M3.2
would take down the transcription task. Suggested fix: compute the cut with
`Duration::checked_mul_f64`-style handling (`try_from_secs_f64`, falling
back to `backoff`), or subtract `backoff.mul_f64(cut)` only when it is
finite, and treat NaN jitter/unit as 0. Then remove the two `#[ignore]`s.
