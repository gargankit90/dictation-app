## Normal typing and Right Option + Shift
Both tests run each sequence with and without Right Option held, with and without side bits: Shift L/R, Cmd L/R, Caps, Fn, each as modifier press/release and with a letter key between, plus mouse down/up. Each event explains its own change, so no resync is sent, the Right Option bit stays in `modifiers` for every event while held, and the final Right Option release gives Pressed, Released and Transcribe.

Right Option + Shift for capitals while dictating is therefore NOT cancelled. The design cancels only when the flags show a tracked modifier change that the event does not account for (a lost event). That is acceptable: a hold that really lost an event is unrecoverable, and discarding is the safe result.

Not covered (no change needed): Right Option released first while Shift stays held, and Shift pressed before Option. They follow the same rule (own-key change only) and I expect no resync. I could not add a test: the callback is private to the vendored crate, which is product code.
