## Untested behaviour found

Added `crates/platform/tests/fakes_contract.rs` (26 tests, public API only):

- **FileAudioSource / WAV decoding**: empty WAV gives zero samples and zero duration; a 0-byte file, a header-only RIFF and a truncated data chunk are each `AudioError::Device` with nothing recording (no panic); 8-, 24- and 32-bit int WAVs scale to exactly 0.5 / -1.0; stereo at full scale stays in `-1.0..=1.0`; a file replaced between recordings is re-read; deleting the file after `start` still lets `stop` return the audio, and the next `start` is `NoDevice`.
- **FakeHotkey**: script events come before emitted ones, in order; the script plays once and a restart takes a new sink; `stop` and a failed `start` drop the sink (trait: "On error the sink is dropped"); 400 emits from 4 threads all arrive; the source can be moved to another thread.
- **Round trips**: clipboard with empty and Unicode text, and recovery after unavailable; secrets kept per name and shared by clones across threads; inserter records from many threads, queued failures used in order; permissions are independent and a denied one isn't re-prompted.
- **FakeClock**: stands still while real time passes and on `advance(0)`; never goes backwards while another thread advances it.
- **Bounds**: every fake fits its port as a `Box<dyn Port>`, so the `Send`/`Sync` supertraits hold.

Minors (tech-debt, don't block):

- #35: these integration tests need `--features testing`, so the gate's `cargo nextest run --workspace` skips them; criterion 3's doctest also flips variant once M1.3 turns the feature on workspace-wide.
- #36: `FakeHotkey` calls the sink while holding its own mutex, so a sink that calls back into the fake (`is_listening`, `emit`) deadlocks. Real sources wouldn't; today's tests use channel sinks.
