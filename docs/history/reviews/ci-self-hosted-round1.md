## Findings

| # | Severity | File:line | Finding | Suggested fix |
| --- | --- | --- | --- | --- |
| 1 | major | `.github/workflows/ci.yml:45`, `.github/workflows/ci.yml:82`, `.github/workflows/dmg.yml:62` | `git clean -ffd` retains every ignored output, rather than just dependency/compiler caches. In particular it retains `src-tauri/permissions/autogenerated/`. The pinned `tauri-build` 2.7.4 reads all permissions under that directory without first deleting obsolete files. For example, after a successful run, a build-script regression that drops `.commands(COMMAND_NAMES)` can still resolve all current capabilities using the retained permission files, and the existing capability tests still see the expected commands. The same source on a fresh checkout fails because those permissions were never generated. Thus a reused checkout can hide a generation failure. | Clean ignored generated source-tree outputs before each job while preserving only the intended caches. For example, use `git clean -ffdx -e /target/ -e /node_modules/`, or explicit equivalent cleanup of all other ignored outputs. Verify the missing-generation case fails on both a warm and fresh checkout. |
| 2 | major | `.github/workflows/ci.yml:24` and `.github/workflows/dmg.yml:43` | `cancel-in-progress: false` protects a running main/manual run, but does not preserve all pending runs in the same concurrency group. All main pushes share `ci-refs/heads/main` or `dmg-refs/heads/main`; when one run is running and two more arrive, the newest replaces the existing pending run. This violates the requested rule that main runs are never cancelled and the comment that these runs queue. A manual run on main shares the same group too. | Keep a stable group per PR, but use a unique run ID for non-PR events, for example `ci-${{ github.event.pull_request.number || github.run_id }}` and the equivalent DMG group. The single runner already serializes jobs. Verify that PR updates share a group while separate main/manual runs have distinct groups. |

For finding 1, `.gitignore` also preserves `dist/`, `src-tauri/gen/`, and `.env*`. Cargo tracks compilation-cache inputs, and `npm ci` replaces Node dependencies, but neither cleans all these source-tree inputs. The concrete permission-generation path was traced through `tauri-build` 2.7.4 `src/acl.rs` (`app_manifest_permissions`) and `tauri-utils` 2.10.2 `src/acl/build.rs` (`autogenerate_command_permissions`). The missing-generation example is a source-level analysis, not a mutation test performed on product files.

For finding 2, GitHub documents that the default concurrency queue keeps only one pending run, replacing it when another arrives; `cancel-in-progress` additionally controls running jobs. See [GitHub's concurrency documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency). A unique non-PR group is sufficient here without adding queue-management machinery.
