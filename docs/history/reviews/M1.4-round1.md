## Developer's open questions

1. **`deny.toml` skips for the `windows@0.58` family:** Narrow and justified. `cargo-deny`'s `krates` graph merges edges across `[graph].targets` (`apple-darwin` pulls in `handy-keys`, and `x86_64-pc-windows-msvc` activates `handy-keys -> windows@0.58.0` alongside `tauri -> windows@0.62`). Pinning the six exact `name@version` entries is narrower than `skip-tree` and carries a clear revisit note for M-W.1.
2. **Untrusted Accessibility reports `NotDetermined`; Microphone unsupported until audio lands:** Agreed. macOS TCC exposes only a boolean (`AXIsProcessTrusted`), so reporting `PermissionStatus::NotDetermined` when untrusted matches `Permissions::check`'s port contract ("if the OS can't say, implementations report `PermissionStatus::NotDetermined`"), and Microphone check belongs to M2.2 (`docs/milestones/M2.2.md`).
3. **`SecureInputWatcher` as a `platform` type rather than a port for now:** Agreed. `docs/ENGINEERING.md` lists no Secure Input port yet, M1.5 wires the Tauri shell, and M4.2 (`docs/milestones/M4.2.md`) introduces Secure Input paste-skip with fakes; avoiding an unused trait in `crates/ports` keeps M1.4 within scope.
4. **Manual criteria 3–5 run by the Lead/owner:** Agreed per `AGENTS.md` workflow step 5; `crates/platform/examples/hotkey_probe.rs` and the PR notes give clear, privacy-safe verification steps without installing hooks or triggering prompts during automated runs.
