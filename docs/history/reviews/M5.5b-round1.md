## Findings by severity

### Minor 1: a newer outage can be lost behind the UI error quota

Location: `crates/app/src/ui_events.rs:68`, interacting with the error drop at
`crates/app/src/ui_events.rs:117`. Follow-up:
[#154](https://github.com/gargankit90/dictation-app/issues/154).

The queue preserves the newest `HotkeyRestored`, but drops a newest
`Error(HotkeyFailed)` when 16 errors already wait unread. A stalled tray consumer
can therefore clear an earlier outage and stay clear during a later outage.

Sleep-free reproduction against the public API: queue 15 `Error(SecureInput)`
events, then `Error(HotkeyFailed)`, `HotkeyRestored`, `Error(HotkeyFailed)`.
Drain into `TrayStatus`. The dropped-error count is 1 and the final title is
`None`, although the latest listener state is down. This is minor because it
requires an accumulated error backlog while the UI consumer is stalled.

Suggested fix: preserve/coalesce the latest hotkey availability transition in
both directions independently of historical errors, while maintaining the queue
bound. Test both possible final availability states through queue and tray.

### Minor 2: recovery leaves the hotkey error overlay visible until its timer

Location: `crates/app/src/overlay.rs:82`. Follow-up:
[#155](https://github.com/gargankit90/dictation-app/issues/155).

`HotkeyRestored` is ignored even when the overlay shows `HotkeyFailed`. For a
short outage, the tray clears and dictation works while the overlay still says
the hotkey isn't working. Pure reproduction: apply `Error(HotkeyFailed)` and
then `HotkeyRestored` to `OverlayModel`; its view remains the error. The stale
message lasts at most the original four-second error timer, so this is minor.

Suggested fix: remember the showing error's kind and hide a hotkey failure on
restoration, retaining unrelated dictation errors and their timers. Add pure
model tests for both cases.

### Minor 3: a newly included vendored test depends on the owner's held keys

Location: `scripts/vendor-tests.sh:70`, enabling
`third_party/handy-keys/src/platform/macos/listener.rs:879`. Follow-up:
[#156](https://github.com/gargankit90/dictation-app/issues/156).

`tap_disabled_pseudo_event_reconciles_modifiers` reads actual session modifier
flags but expects empty modifiers. When the test process has Accessibility,
the owner holding Ctrl or Shift during the self-hosted gate can fail an otherwise
correct build. The source explicitly assumes no physically held modifiers.

I simulated that environment in the `/tmp` copy by substituting
`CGEventFlags::MaskControl` for the pseudo-event handler's flags query. The
named test failed with `Modifiers(CTRL_LEFT)` versus empty and exit 101. No keys
were posted and the owner's keyboard state was untouched. This demonstrates a
test environment dependency, not incorrect production reconciliation.

Suggested fix: inject controlled session flags for this test; the callback
context already has a session-flags seam elsewhere. Keep the full vendored
library suite in the gate.

## Correctness checked

- The supervisor parks on a condition variable while healthy and between
  retries. Backoff is 0.5, 1, then 2 seconds indefinitely; stopping marks the
  delivery closed, notifies the waiter, releases locks, then joins it.
- Restarts and Settings changes serialize on `state`; delivery does not acquire
  `state`, and source stop/join happens outside the delivery lock. A dead source
  is stopped before its replacement starts. The restart reads the current spec
  under the same state lock.
- Settings handoff deliberately overlaps source lifetimes briefly, but the
  delivery generation allows only one source's events through. Pending presses
  and pending failures are carried into the handoff; stale old events are
  discarded. I independently exercised a Settings change racing a paused
  restart, then emitted from every fake: exactly one source remained listening,
  F6 was current, and exactly one press reached the sink.
- Missing Accessibility at first launch produces `Failed` without aborting
  pipeline startup. The supervisor retains the sink, retries, and emits
  `Restored` after a successful handoff. Removal of `PermissionTolerantHotkey`
  leaves this recovery path available in release builds too.
- The pipeline maps restoration directly to the UI; ordinary tray failure and
  restoration transitions clear at handoff. The overlay and saturated-queue
  exceptions are the minors above.
- Esc repeat/up reconcile a missed modifier release while preserving normal
  Esc cancellation. Unmapped keys carry reconciled modifiers, can release a
  stuck hold, and cannot start a hold. Fn remains ignored.
- Debug outage commands are ignored in release builds. The outage wrapper
  disconnects delivery and refuses new sources while down; the VM scenario
  subsequently uses a real listener and real hotkey holds.
