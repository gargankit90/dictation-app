# Engineering rules

How dictation-app is built. Every agent follows these; the Code Reviewer
checks them (`docs/review-checklist.md`). Changing a rule needs the Lead's
agreement and a commit to this file.

## Architecture: ports and adapters

All logic lives in plain Rust crates with no OS or Tauri dependency. OS
features sit behind traits with a Mac adapter, a Windows adapter and a fake.
Tauri is a thin layer on top.

| Crate | Package | Holds | May depend on |
| --- | --- | --- | --- |
| `crates/core` | `dictation-core` | coordinator state machine, events, text cleanup, audio maths, WAV, settings, hotkey specs, retry policy, errors | nothing in the workspace |
| `crates/ports` | `dictation-ports` | traits: `HotkeySource`, `AudioSource`, `Transcriber`, `TextInserter`, `Clipboard`, `SecretStore`, `Permissions`, `Clock` | `core` |
| `crates/platform` | `dictation-platform` | OS adapters; fakes behind feature `testing` | `core`, `ports` |
| `crates/transcribe` | `dictation-transcribe` | `Transcriber` implementations: OpenAI-compatible (Groq/OpenAI), mock; later local | `core`, `ports` |
| `crates/app` | `dictation-pipeline` | async pipeline that runs the coordinator against the ports; no Tauri types | `core`, `ports` |
| `src-tauri` | `dictation-app` | Tauri commands, events, tray, windows, plugins, CLI flags | everything above |
| `src/` | | React UI | Tauri commands/events only |

- **Dependencies point inward.** A crate never depends on one to its right in
  `src-tauri → app → ports ← platform/transcribe`.
- **The coordinator is a pure function**: `step(state, event) -> (state,
  Vec<Command>)`. The app layer carries out the commands. Every behaviour rule
  gets a plain unit test with no threads, timers or mocks.
- **`#[cfg(target_os)]` only in `platform`.** Everything else compiles
  unchanged on Mac and Windows.
- **Typed IPC:** the UI uses only commands and events generated by
  `tauri-specta`, so Rust and TS types can't drift.
- A crate gains a dependency on another only in the milestone that first uses
  it (`cargo machete` must stay clean).

## Rust

- `cargo fmt`; `cargo clippy --workspace --all-targets -- -D warnings`;
  `clippy::pedantic` on in `core`.
- `#![forbid(unsafe_code)]` in `core`, `ports`, `transcribe` and `app`.
  `unsafe` is allowed only in `platform`, each block with a `// SAFETY:`
  comment saying why it's sound.
- Errors: `thiserror` enums in libraries; `anyhow` only in `src-tauri`.
- No `unwrap()`, `expect()`, `panic!`, `todo!` or `unimplemented!` outside
  tests (clippy `unwrap_used`, `expect_used`). Where one is truly impossible to
  avoid, `#[allow]` it with a reason.
- Never block the audio callback or the main thread. Audio goes over channels
  or a ring buffer; network and file work is async on tokio.
- Logging with `tracing`, to a rotating log file testers can send. **Never log
  API keys or transcripts at info level or above.** Debug level may log
  transcript lengths, not text.
- Public items get a short doc comment. Comments explain *why*, not *what*.
- The toolchain is pinned in `rust-toolchain.toml`. Dependency versions are
  workspace dependencies in the root `Cargo.toml`.
- `cargo deny` (licences, advisories, duplicates) and `cargo machete` (unused
  dependencies) must pass.

## Tauri 2

- Each window gets only the commands it needs, through
  `src-tauri/capabilities/*.json`. The overlay gets almost none.
- Strict CSP; no remote content.
- Commands stay thin: validate input, call `app`, map errors.
- Secrets stay in Rust. The UI can set or test the API key, never read it back.
- One instance per user through `dictation_platform::single_instance` (a
  lock file plus a socket with bounded reads; it replaced the single-instance
  plugin in M1.7), with CLI flags forwarded (`--press`/`--release` are test
  hooks). Updater plugin with a minisign key.

## TypeScript / React

- TypeScript `strict` (plus `noUncheckedIndexedAccess`), ESLint with
  typescript-eslint strict and react-hooks, Prettier.
- No global state library until it's needed.
- Vitest + React Testing Library; mock Tauri with `@tauri-apps/api/mocks`
  `mockIPC`.
- Exact dependency versions (`.npmrc` `save-exact`); Node 24 only.

## Security and privacy

- API keys only in the OS keychain (`keyring`). Never in settings files, logs,
  the repo, test fixtures, PR comments or reports.
- Audio stays in memory; written to disk only in debug mode.
- No analytics or telemetry.
- Skip pasting when a password field (Secure Input) is focused.
- New network calls go only to the configured transcription provider.

## Code reuse and licences

- Adapt code only from permissive repos: Handy, OpenWhispr, FreeFlow, Muesli,
  transcribe.cpp (MIT), FluidAudio (Apache-2.0). Credit each in `NOTICE`, and
  name the source file in a comment where the code came from.
- FluidVoice and VoiceInk are GPLv3: read for ideas, never copy code.
  `cargo deny` only checks dependencies, so the Code Reviewer checks this.

## Signing

- Sign every build with one self-signed certificate, `dictation-app Dev`, in
  the login keychain (from M0.3), like FreeFlow's `CODESIGN_IDENTITY ?=
  FreeFlow Dev`. macOS ties Accessibility and Microphone permission to the
  signature, so a fixed certificate keeps permissions across rebuilds and
  updates.
- Gatekeeper still blocks the first launch until we sign with a Developer ID.

## OS behaviour rules

- **Clipboard:** mark every write with `org.nspasteboard.TransientType`,
  `ConcealedType` and `AutoGeneratedType` so clipboard managers skip it.
  Restore the user's clipboard only if our session marker is still on it.
- **Hotkey:** default is modifier-only (Right Option). Under Secure Input,
  normal-key shortcuts stop silently while modifier-only ones keep working;
  show a warning while Secure Input is on.
- **Accessibility grant while running (#50, M5.2):** an app bundle doesn't
  need a relaunch to see a grant made in System Settings:
  `AXIsProcessTrusted()` turns true in the running process, and the hotkey
  supervisor (M5.5b) then starts a new event tap by itself. Onboarding's
  Accessibility step polls it every second and moves on by itself. FreeFlow
  and Muesli build their onboarding on the same polling. The #50 report was
  a command-line probe run from Terminal: there the grant belongs to
  Terminal (the responsible process) and didn't reach the probe while it
  ran, which is the case the relaunch advice is about. Not yet watched with
  a real grant in our VM, since SIP keeps the TCC database out of a script's
  reach and the grant's password sheet refuses synthetic keys: that needs a
  person at the VM's display (M5.2 criterion 4). Until then, once the user
  has opened System Settings, the step also says "Relaunch to finish" with a
  Relaunch button, which restarts the app and reopens onboarding.
- **Overlay:** a non-activating panel that never takes focus
  (`tauri-nspanel`), or the paste lands in the overlay.
- **Recording length:** maximum 5 minutes (16 kHz mono WAV ≈ 1.9 MB/min, so
  about 9.6 MB, under Groq's upload limit).
- **Groq upload limit** (checked 2026-10-31 at
  <https://console.groq.com/docs/speech-to-text>): a direct file upload may
  be up to 25 MB on the free tier and 100 MB on the dev (paid) tier; larger
  files must be passed by URL instead. Requests shorter than 10 s are billed
  as 10 s. We upload directly, so we plan for the 25 MB free-tier limit.

## Tests

Every testable behaviour gets a test, at the cheapest level that catches it.

| Level | Where | Runs |
| --- | --- | --- |
| Unit | next to the code (`#[cfg(test)]`), Vitest for UI | milliseconds, no OS or network |
| Integration | `crates/*/tests/` with fakes and `wiremock` | seconds, no real OS or network |
| End-to-end | `tests/e2e/`, the built app inside the Lume VM | minutes, scripted |

- Tests go in the same commit as the code, or the commit before it (red, then
  green).
- Coverage: `core` and `transcribe` ≥ 85%, `app` ≥ 70% (`cargo llvm-cov`).
- Property tests (`proptest`) for the coordinator.
- No sleeps for timing in unit tests: inject a `Clock`.
- Only these stay manual: real key timing, real mic quality, macOS permission
  prompts, and pasting into other apps (Slack, Chrome, VS Code, Terminal).

## Quality gate

Runs in git's pre-push hook (`lefthook run pre-push-gate`) and CI (from M0.3);
every finding is fixed.

| Check | Tool | Gate |
| --- | --- | --- |
| Format | `cargo fmt --check`, `prettier --check` | must pass |
| Rust lint | `cargo clippy --workspace --all-targets -- -D warnings` | zero warnings |
| Dependencies | `cargo deny check`, `cargo machete` | must pass |
| Rust tests | `cargo nextest run --workspace` + doc tests | all green |
| Coverage | `cargo llvm-cov` | thresholds above |
| TS | `tsc --noEmit`, `eslint --max-warnings 0`, `vitest run` | all green |
| Spelling | `typos` | must pass |

A suppression (`#[allow]`, `eslint-disable`) needs a comment explaining why,
and the Code Reviewer must agree.

## CI runner

CI (`.github/workflows/ci.yml`, `dmg.yml`) runs on the owner's Mac, a
self-hosted GitHub Actions runner, because GitHub-hosted jobs are blocked by
account billing.

- **Where:** `~/actions-runner` on the owner's Mac, registered as
  `owner-mac-m4pro` and running as the owner's macOS user, one job at a time.
  Labels: `self-hosted`, `macOS`, `ARM64`, `owner-mac`. Jobs use
  `runs-on: [self-hosted, macOS, owner-mac]`.
- **The Mac must be awake** and online. If it sleeps or is off, jobs wait in
  the queue until it is back (then they time out after GitHub's limit).
- **Tools** are installed by hand, not downloaded per run: the pinned Rust
  toolchain, Node (the major in `.nvmrc`), cargo-nextest, cargo-deny,
  cargo-machete, cargo-llvm-cov, cargo-about and typos.
  `scripts/ci-check-tools.sh` fails a job early and names a missing tool.
  When a version pin in `gate.sh`-related files changes, update the Mac too.
- **Caches** are local: the checkout keeps `target/` and `node_modules/`
  between runs (`clean: false`, then `git clean -ffdx -e /target/ -e
  /node_modules/`). No `actions/cache` or rust-cache upload.
- **Nothing else survives a run:** the `-x` clean also removes ignored
  generated files (`src-tauri/permissions/autogenerated/`, `src-tauri/gen/`,
  `dist/`, `.env*`), so a reused checkout cannot hide a missing generation
  step. Keep a new cache only by adding an explicit `-e` to the clean step in
  both workflows. `scripts/build-dmg.sh` also clears
  `target/<profile>/bundle/dmg` before bundling, so it never picks up an
  older DMG from the kept `target/`.
- **Safety:** pull requests run only from branches in this repository, never
  forks; `pull_request_target` is not used; the token is `contents: read`;
  CI never touches the Lume VMs, and runs no e2e tests. The DMG job signs ad
  hoc (`DMG_ADHOC=1`), so it never uses the owner's dev certificate.
- **One run per PR:** a new push cancels the superseded run. The concurrency
  group is the PR number for pull requests and the run id for everything
  else, so pushes to `main` and manual runs each get their own group: none is
  cancelled, none replaces another that is pending (a shared group keeps only
  one pending run), and the single runner works through them in turn.
- **Fall back to hosted runners:** in both workflow files change `runs-on`
  back to `ubuntu-24.04` (gate) or `macos-latest` (platform crate, DMG), drop
  the `scripts/ci-check-tools.sh` steps and add back
  `taiki-e/install-action` (tools as pinned in the old workflow, see git
  history) and `Swatinem/rust-cache`. The gate on Linux also needs the Tauri
  system libraries (`libwebkit2gtk-4.1-dev`, `libjavascriptcoregtk-4.1-dev`,
  `libsoup-3.0-dev`, `libgtk-3-dev`, `pkg-config`) and freed disk space; copy
  those steps from the history of `ci.yml` before this change.

## Git

- Trunk-based; `main` is always green and changes only by merging a PR.
- One short-lived branch per milestone: `m<id>-<slug>`.
- Conventional Commits, one logical change each: `feat(core): …`,
  `test(core): …`, `fix(platform): …`, `docs: …`, `chore: …`.
- Hooks: `scripts/install-hooks.sh` installs them. pre-commit (lefthook) runs
  fast checks on staged files; pre-push runs `scripts/pre-push`: the push
  guard, then the full gate (from M0.3). Never skip them.
- PRs merge with a merge commit, by the Code Reviewer, after `Tester: PASS`,
  `Reviewer: APPROVED` and the Lead's manual checks. Each merged milestone is
  tagged `m<id>`.
- Findings are rated **blocker**, **major** or **minor**. Blockers and majors
  are fixed before merging; minors are fixed or recorded as a
  GitHub issue labelled `tech-debt`, with a reason, linked from the PR.
