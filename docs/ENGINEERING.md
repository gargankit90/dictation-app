# Engineering rules

How dictation-app is built. Every agent follows these; the Code Reviewer
checks them (`docs/review-checklist.md`). Changing a rule needs the Lead's
agreement and a commit to this file.

## Architecture: ports and adapters

All logic lives in plain Rust crates with no OS or Tauri dependency. OS
features sit behind traits with a Mac adapter, a fake and, planned, a Windows
adapter. Tauri is a thin layer on top.

| Crate | Package | Holds | May depend on |
| --- | --- | --- | --- |
| `crates/core` | `dictation-core` | coordinator state machine, events, text cleanup, audio maths, WAV, settings, hotkey specs, retry policy, errors | nothing in the workspace |
| `crates/ports` | `dictation-ports` | traits: `HotkeySource`, `AudioSource`, `Transcriber`, `TextInserter`, `Clipboard`, `SecretStore`, `Permissions`, `Clock` | `core` |
| `crates/platform` | `dictation-platform` | OS adapters; fakes behind feature `testing` | `core`, `ports` |
| `crates/transcribe` | `dictation-transcribe` | `Transcriber` implementations: OpenAI-compatible (Groq/OpenAI), mock; later local | `core`, `ports` |
| `crates/telemetry` | `dictation-telemetry` | PostHog adapter for the `Telemetry` port, Sentry adapter for `ErrorReporter`, and the install ID | `ports` |
| `crates/app` | `dictation-pipeline` | async pipeline that runs the coordinator against the ports; no Tauri types | `core`, `ports` |
| `src-tauri` | `dictation-app` | Tauri commands, events, tray, windows, plugins, CLI flags | everything above |
| `src/` | | React UI | Tauri commands/events only |

- **Dependencies point inward.** A crate never depends on one to its right in
  `src-tauri → app → ports ← platform/transcribe`.
- **The coordinator is a pure function**: `step(state, event) -> (state,
  Vec<Command>)`. The app layer carries out the commands. Every behaviour rule
  gets a plain unit test with no threads, timers or mocks.
- **`#[cfg(target_os)]` only in `platform`.** Everything else compiles
  unchanged on Mac and Windows.
- **Typed IPC:** the UI uses only commands and events generated by
  `tauri-specta`, so Rust and TS types can't drift.
- A crate gains a dependency on another only in the milestone that first uses
  it (`cargo machete` must stay clean).

## Rust

- `cargo fmt`; `cargo clippy --workspace --all-targets -- -D warnings`;
  `clippy::pedantic` on in `core`.
- `#![forbid(unsafe_code)]` in `core`, `ports`, `transcribe` and `app`.
  `unsafe` is allowed only in `platform`, each block with a `// SAFETY:`
  comment saying why it's sound.
- Errors: `thiserror` enums in libraries; `anyhow` only in `src-tauri`.
- No `unwrap()`, `expect()`, `panic!`, `todo!` or `unimplemented!` outside
  tests (clippy `unwrap_used`, `expect_used`). Where one is truly impossible to
  avoid, `#[allow]` it with a reason.
- Never block the audio callback or the main thread. Audio goes over channels
  or a ring buffer; network and file work is async on tokio.
- Logging with `tracing`, to a rotating log file testers can send. **Never log
  API keys or transcripts at info level or above.** Debug level may log
  transcript lengths, not text.
- Public items get a short doc comment. Comments explain *why*, not *what*.
- The toolchain is pinned in `rust-toolchain.toml`. Dependency versions are
  workspace dependencies in the root `Cargo.toml`.
- `cargo deny` (licences, advisories, duplicates) and `cargo machete` (unused
  dependencies) must pass.

## Tauri 2

- Each window gets only the commands it needs, through
  `src-tauri/capabilities/*.json`. The overlay gets almost none.
- Strict CSP; no remote content.
- Commands stay thin: validate input, call `app`, map errors.
- Secrets stay in Rust. The UI can set or test the API key, never read it back.
- One instance per user through `dictation_platform::single_instance` (a
  lock file plus a socket with bounded reads; it replaced the single-instance
  plugin in M1.7), with CLI flags forwarded (`--press`/`--release` are test
  hooks).
- Updates (M5.4): `tauri-plugin-updater` trusts only the owner's minisign
  public key in `tauri.conf.json` and fetches `latest.json` from this repository's
  GitHub Releases (`gargankit90/dictation-app`; only download URLs under its
  `releases/download/` are accepted; the old `dictation-app-releases` is
  archived and was never used for a release). It checks quietly at launch and from
  the tray; nothing installs until the user picks "Install and restart",
  which restarts through the normal exit (`request_restart`, as M5.2's
  relaunch). Releases are signed `dictation-app Dev` so Microphone and
  Accessibility survive an update. `scripts/release.sh` builds a release on
  the owner's Mac with the private key from the Keychain (never printed or
  written); `docs/releasing.md` has the steps. Tests use throwaway keys only.

## TypeScript / React

- TypeScript `strict` (plus `noUncheckedIndexedAccess`), ESLint with
  typescript-eslint strict and react-hooks, Prettier.
- No global state library until it's needed.
- Vitest + React Testing Library; mock Tauri with `@tauri-apps/api/mocks`
  `mockIPC`.
- Exact dependency versions (`.npmrc` `save-exact`); Node 24 only.

## Security and privacy

- API keys only in the OS keychain (`keyring`). Never in settings files, logs,
  the repo, test fixtures, PR comments or reports.
- Audio stays in memory; written to disk only in debug mode.
- Recent dictations (U7, `docs/privacy.md`): text only, in a 0600 file in the
  app's data folder. Never in logs (neither an entry's text nor its length),
  analytics, Sentry or the report, and a paste Secure Input refused is never
  kept. `Entry` has no field for an app or window.
- Anonymous usage events (A1) are **on by default**, with an off switch in
  Settings → Privacy that stops sending at once, clears the queue and deletes
  the install ID. They go only to PostHog Cloud US, sent from Rust through
  the `Telemetry` port (`crates/ports`, adapter `crates/telemetry`), never
  from the webview. Events are a closed enum of enums, buckets and version
  numbers. **Never sent:** audio, transcripts, typed or pasted text, API
  keys, app names, bundle IDs or window titles, file paths, hostnames,
  usernames, IP addresses (we send no `$ip`; the PostHog project must also
  be set to discard IPs). The identity is a random install ID (not from
  hardware) with person profiles off. A build without `DICTATION_POSTHOG_KEY`
  sends nothing. A new event or property needs a variant in
  `crates/ports/src/telemetry.rs`, an entry in `docs/privacy.md` and the
  "What's sent" list, and the privacy test in
  `crates/app/tests/usage_privacy.rs` must still pass.
- Error reports (A2) share A1's switch. They go only to Sentry (US) through
  the `ErrorReporter` port (adapter `crates/telemetry/src/errors.rs`), and an
  event is built from an allow-list: release, environment, the E1 error code
  and A1 error type, and for a panic crate-relative frames. Never a message.
  No native crash dumps (they hold raw memory). A build without
  `DICTATION_SENTRY_DSN` sends nothing. Any new field needs an entry in
  `docs/privacy.md` and the "What's sent" list.
- Skip pasting when a password field (Secure Input) is focused.
- New network calls go only to the configured transcription provider, the
  update server and the usage-events host above.

## Code reuse and licences

- Adapt code only from permissive repos: Handy, OpenWhispr, FreeFlow, Muesli,
  transcribe.cpp (MIT), FluidAudio (Apache-2.0). Credit each in `NOTICE`, and
  name the source file in a comment where the code came from.
- FluidVoice and VoiceInk are GPLv3: read for ideas, never copy code.
  `cargo deny` only checks dependencies, so the Code Reviewer checks this.

## Signing

- Sign every build with one self-signed certificate, `dictation-app Dev`, in
  the login keychain (from M0.3), like FreeFlow's `CODESIGN_IDENTITY ?=
  FreeFlow Dev`. macOS ties Accessibility and Microphone permission to the
  signature, so a fixed certificate keeps permissions across rebuilds and
  updates.
- Gatekeeper still blocks the first launch until we sign with a Developer ID.

## OS behaviour rules

- **Clipboard:** if Secure Input is on (a password field has focus),
  don't paste and don't touch the clipboard; if it comes on after the
  transcript is written, don't send the chord and put the user's
  clipboard back at once. Otherwise mark every dictation write with
  `org.nspasteboard.TransientType`, `ConcealedType` and
  `AutoGeneratedType` so clipboard managers skip it, and save all of the
  user's items and representations first. Paste with ⌘V, then put the
  saved clipboard back `RESTORE_DELAY` (1.5 s) after the chord, on a
  background timer that never blocks the event loop or the hotkey, and
  only if the clipboard still holds our write (our session token and the
  change count right after it); if anything else changed it, drop the
  saved clipboard: a newer copy always wins. A dictation that starts
  while a restore is pending first does that restore synchronously,
  under the same rule (a brief, bounded wait: a few pasteboard calls),
  then saves the clipboard. At quit or relaunch, finish a pending
  restore at its due time (at most `RESTORE_DELAY` after the last chord,
  never earlier) before the app exits, waiting at most 2 s in all; past
  that, quit anyway. Nothing in the paste may wait on the main thread
  (the shutdown blocks it): work out the paste key from the keyboard
  layout ahead of time, at startup and on input source changes. If the
  chord can't be sent, leave the transcript on the clipboard and say so
  in the error. If the chord is sent but nothing reads it (no text field
  has focus), the restore still runs at `RESTORE_DELAY`: the transcript
  leaves the clipboard, and stays recoverable through Copy last
  dictation (U5) and the dictation history (U7). Don't read the target
  app (Accessibility) to decide when to restore. A target that reads the
  clipboard later than `RESTORE_DELAY` pastes the user's old clipboard;
  raise the constant if that is ever seen.
- **Hotkey:** default is modifier-only (Right Option). Under Secure Input,
  normal-key shortcuts stop silently while modifier-only ones keep working;
  show a warning while Secure Input is on.
- **Accessibility grant while running (#50, M5.2):** an app bundle doesn't
  need a relaunch to see a grant made in System Settings:
  `AXIsProcessTrusted()` turns true in the running process, and the hotkey
  supervisor (M5.5b) then starts a new event tap by itself. Onboarding's
  Accessibility card polls it every second and turns "✓ Allowed" by itself. FreeFlow
  and Muesli build their onboarding on the same polling. The #50 report was
  a command-line probe run from Terminal: there the grant belongs to
  Terminal (the responsible process) and didn't reach the probe while it
  ran, which is the case the relaunch advice is about. Not yet watched with
  a real grant in our VM, since SIP keeps the TCC database out of a script's
  reach and the grant's password sheet refuses synthetic keys: that needs a
  person at the VM's display (M5.2 criterion 4). Until then, once the user
  has opened System Settings, the card also offers "Relaunch and resume",
  which restarts the app and reopens onboarding at the same step, and so does
  a grant that stays unapplied (allowed, with the hotkey still down).
- **Overlay:** a non-activating panel that never takes focus
  (`tauri-nspanel`), or the paste lands in the overlay. An event sent to its
  page before the page's listener is registered is lost, so the page says
  when it listens (its document title; it may not call commands) and the
  app sends the current view again (#119). Checked by
  `e2e_overlay_rendered_states_and_error` (T4b).
- **Microphone permission:** the first press asks (the macOS prompt); an
  "Allow" there works at once. After "Don't Allow", a grant in System
  Settings › Privacy & Security › Microphone reaches the app only after it
  is quit and reopened: macOS 15 keeps reporting the refusal to the running
  app (`AVCaptureDevice` authorization status, checked in the VM over 25 s,
  T4b). So the error says to allow it there and relaunch the app from the menu bar. Checked by
  `e2e_microphone_denied_then_recover` (#126).
- **Paste target:** the text goes to whatever has keyboard focus when it is
  pasted, not where the dictation started. A user who switches windows (or
  apps) while a transcription is pending gets the text in the new one; the
  app doesn't remember or restore the first target, and none of its own
  windows (the overlay, Settings) takes focus on the way. Checked by
  `e2e_focus_switch_during_transcription` (T4a, #117).
- **Recording length:** maximum 5 minutes (16 kHz mono WAV ≈ 1.9 MB/min, so
  about 9.6 MB, under Groq's upload limit).
- **Groq upload limit** (checked 2026-10-31 at
  <https://console.groq.com/docs/speech-to-text>): a direct file upload may
  be up to 25 MB on the free tier and 100 MB on the dev (paid) tier; larger
  files must be passed by URL instead. Requests shorter than 10 s are billed
  as 10 s. We upload directly, so we plan for the 25 MB free-tier limit.

## Tests

Every testable behaviour gets a test, at the cheapest level that catches it.

| Level | Where | Runs |
| --- | --- | --- |
| Unit | next to the code (`#[cfg(test)]`), Vitest for UI | milliseconds, no OS or network |
| Integration | `crates/*/tests/` with fakes and `wiremock` | seconds, no real OS or network |
| End-to-end | `tests/e2e/`, the built app inside the Lume VM | minutes, scripted |

- Tests go in the same commit as the code, or the commit before it (red, then
  green).
- Coverage: `core` and `transcribe` ≥ 85%, `app` ≥ 70% (`cargo llvm-cov`).
- Property tests (`proptest`) for the coordinator.
- No sleeps for timing in unit tests: inject a `Clock`.
- Only these stay manual: real key timing, real mic quality, macOS permission
  prompts, and pasting into other apps (Slack, Chrome, VS Code, Terminal).

## Quality gate

Runs in git's pre-push hook (`lefthook run pre-push-gate`) and CI (from M0.3);
every finding is fixed. Locally it skips work it has already done, see below.

| Check | Tool | Gate |
| --- | --- | --- |
| Format | `cargo fmt --check`, `prettier --check` | must pass |
| Rust lint | `cargo clippy --workspace --all-targets -- -D warnings` | zero warnings |
| Dependencies | `cargo deny check`, `cargo machete` | must pass |
| Rust tests | `cargo nextest run --workspace` + doc tests | all green |
| Coverage | `cargo llvm-cov` | thresholds above |
| TS | `tsc --noEmit`, `eslint --max-warnings 0`, `vitest run` | all green |
| Spelling | `typos` | must pass |

A suppression (`#[allow]`, `eslint-disable`) needs a comment explaining why,
and the Code Reviewer must agree.

### Not running the same checks twice (G2)

The rule stays: run the gate before you push. `scripts/gate.sh` (helpers in
`scripts/gate-lib.sh`, tests in `scripts/test-gate.sh`) decides what that costs:

- **Receipt.** A full pass on a clean tree writes a receipt (atomically, at the
  very end; a failure or interruption writes none) in the worktree's git
  directory, outside the tracked tree. A later run on identical input is
  skipped. The key covers the tree (a dirty tree, untracked non-ignored files
  included, never reuses or writes a receipt), the gate scripts, OS and
  architecture, Rust, Node and check-tool versions, env flags and profiles
  (`NEXTEST_*`, `CARGO_*`, `RUST*`, `DICTATION_*`, `LLVM_*`), and the installed
  npm packages. It expires after 4 hours (`GATE_RECEIPT_TTL`, seconds) so
  advisory and dependency checks don't go stale.
- **Prose shortcut.** When every file changed against the merge base of
  `origin/main` is on a short allowlist of plain Markdown, only prettier, typos
  and the link check run. Unknown paths, deletions or renames out of the
  allowlist, an empty diff, a dirty tree, a detached HEAD, a shallow clone, a
  missing `origin/main`, or several merge bases run the full gate; the base,
  candidate, mode and reason are printed. Not on the allowlist: `AGENTS.md`,
  `CLAUDE.md`, `SECURITY.md`, `CHANGELOG.md`, `NOTICE`, licences,
  `docs/TESTERS.md`, `docs/releasing.md`, `docs/privacy.md`, `docs/agents/`,
  `site/`, `.github/`, `scripts/`, `.claude/`.
- **`scripts/gate.sh --full`** ignores both. **CI** (`CI` or `GITHUB_ACTIONS`
  set) always runs everything and never reads or writes a receipt. Tag pushes
  get no special case: a receipt either matches or it doesn't.
- **Only on the owner's Mac** (the macOS CI job runs the Rust checks only):
  coverage thresholds and the shell self-tests (`test-guards`, `test-release`,
  `test-check-licences`, `test-coverage`, `test-gate`, the e2e stub tests) run
  in the full gate on Linux CI and locally, not on the macOS runner.

## CI

CI (`.github/workflows/ci.yml`, `dmg.yml`) runs on GitHub-hosted runners for
every pull request (forks included) and every push to `main`. The repository
is public, and a pull request can edit workflow files, so **no workflow may
reach the owner's Mac**: there is no self-hosted runner, and
`scripts/check-workflows.sh` (part of the gate) fails on one.

- **Jobs:** `gate` runs `scripts/gate.sh` on `ubuntu-24.04` after installing
  the Tauri system libraries (`libwebkit2gtk-4.1-dev`,
  `libjavascriptcoregtk-4.1-dev`, `libsoup-3.0-dev`, `libgtk-3-dev`,
  `pkg-config`), freeing disk space, and the pinned gate tools
  (`taiki-e/install-action`: cargo-about, cargo-deny, cargo-machete,
  cargo-nextest, cargo-llvm-cov, typos) with `Swatinem/rust-cache`. `macos`
  builds, lints and tests `dictation-platform` and `dictation-transcribe` (the Metal build of the on-device engine, #219) on `macos-15` (Apple Silicon,
  checked with `uname -m`), the `#[cfg(target_os = "macos")]` code Linux
  compiles out, then also runs workspace clippy, nextest and doctests with
  `DICTATION_NO_LAUNCH=1` (G2), so every crate's tests run on a Mac too. `dmg.yml` builds the tester DMG on `macos-15`, signed ad hoc
  (`DMG_ADHOC=1`): there is no certificate and no secret in CI.
- **Job names are stable** (they become required status checks): `Quality gate (Linux)`,
  `Platform crate (macOS)` and, for packaging changes, `DMG (macOS)`. Renaming
  one breaks the required check.
- **Rules for every workflow** (checked by `scripts/check-workflows.sh`):
  top-level `permissions: contents: read`; every action pinned to a full
  commit SHA (with the version in a comment); `actions/checkout` with
  `persist-credentials: false`; no `pull_request_target`, no `workflow_run`,
  no `secrets.` reads; `runs-on` one hosted image. `workflow_dispatch` stays
  only where it is harmless on a hosted runner (CI, DMG).
- **When a pinned tool version changes,** update the `tool:` line in
  `ci.yml` (and `dmg.yml` for cargo-about) with it.
- **One run per PR:** a new push cancels the superseded run. The concurrency
  group is the PR number for pull requests and the run id for everything
  else, so pushes to `main` and manual runs are never cancelled.
- **VM e2e is local, not in CI.** The Lume VMs live on the owner's Mac, so no
  workflow starts them (the old `e2e.yml` is gone, #168). After each merge
  the Lead runs `scripts/e2e-main.sh [<sha>]` on that Mac. It fetches
  `origin/main`, refuses a SHA not reachable from it, checks the commit out
  into a fresh temporary worktree, runs `tests/e2e/ci-run.sh` there (build,
  then a free VM through `run.sh`'s lock) and keeps the evidence under
  `target/e2e-main-evidence/<sha12>-<time>/`: a few KB on a pass, everything
  on a failure (#174). Details: `tests/e2e/README.md`.

## Git

- Trunk-based; `main` is always green and changes only by merging a PR.
- One short-lived branch per milestone: `m<id>-<slug>`.
- Conventional Commits, one logical change each: `feat(core): …`,
  `test(core): …`, `fix(platform): …`, `docs: …`, `chore: …`.
- Hooks: `scripts/install-hooks.sh` installs them. pre-commit (lefthook) runs
  fast checks on staged files; pre-push runs `scripts/pre-push`: the push
  guard, then the full gate. Never skip them.
- PRs merge with a merge commit, by the Code Reviewer, after `Tester: PASS`,
  `Reviewer: APPROVED` and the Lead's manual checks. Each merged milestone is
  tagged `m<id>`.
- Findings are rated **blocker**, **major** or **minor**. Blockers and majors
  are fixed before merging; minors are fixed or recorded as a
  GitHub issue labelled `tech-debt`, with a reason, linked from the PR.

### Claude command hook and ruleset audit (G1)

`.claude/hooks/guard-git.sh` is a best-effort matcher for plain merge,
destructive repository API and guard-write commands. It fails open for
unreadable input, unparsable shell and heredocs. It neither executes the
inspected command nor reads files named in it. Read-only guard references,
multiline scripts, unrelated settings.json files and hook-bypass settings
pass. Skipping hooks remains prohibited by AGENTS.md; required CI enforces
the gate. Edit/Write denies remain, and the four static push denies are gone.
The pre-push guard, pre-push runner and installer are unchanged; no reinstall
is needed.

A deliberately disguised command can get past the hook. We accept this
trade-off to avoid false positives. The hosted daily `rulesets.yml` workflow
compares names, enforcement, target, conditions and rules against
`.github/rulesets-expected.json`, catching visible ruleset drift afterwards.
It uses only `contents: read` and no secrets. Missing rulesets, API errors
and policy differences fail the run; ordering and API metadata do not.
GitHub omits `bypass_actors` without ruleset write access ([API documentation](https://docs.github.com/en/rest/repos/rules#get-a-repository-ruleset)),
so the workflow logs that limitation and cannot attest bypass policy.
The Lead runs `python3 scripts/check-rulesets.py --require-bypass` locally
with the existing admin `gh` token to check bypass actors as well; it fails
if that field is hidden. The owner must enable GitHub workflow-failure email
notifications to receive scheduled failure alerts. The audit cannot repair
a changed policy or protect itself from an admin disabling the workflow.

GitHub disables scheduled workflows in public repositories after 60 days
without repository activity; this daily audit then stops until the workflow
is re-enabled. The Lead should check the schedule remains enabled and, after
merging G1-simple-guard, run `gh workflow run rulesets.yml` once and verify
the first hosted read-only-token run is green.
